# C18 · 生产产物污染清洗与派发沙箱修复（artifact-contamination）

## 背景（根因 + 证据）

**根因**：LLM 派发沙箱的写权限制未在派发层解决，而是把"只读沙箱无法写入，请手动复制"的元叙述泄漏进产物；同时手动/DEBUG 模式跑出的自证缺陷（手算分数、时间戳编造）混入生产树——产物既污染交付物，又作为下游输入二次扩散进快照（phase4 §1 候选元根因 G）。

代表证据：
- **F1171**（P1，verified，权威复扫）：全树元叙述污染实为 **109 文件**（audits 55 + snapshots 37 + staging 9 + decisions 7 + 正文 ch35 1）——r1 报 67 且分层不可复现；污染扩展至正文交付物与快照二次嵌埋（协调者抽验 ch35:338 与 snapshots 证实）
- **F1162**（P1，verified）：audits 全域 12 维度覆盖 35/56 章 + **2 章 resonance 分数自证手动计算**
- **F1108**（P1）：审计波冗余 6.2MB 审计对 1.3MB 正文（4.64x），并在快照内二次嵌埋
- **F1172**（P2）：ch51 resonance 手算 trend 五行三窗口两错值 + 超阈值断言为假（70-65=5 恰在边界带）——铁律 3（分数必须机器算）违反的实际后果实证
- P2 族：F1117（验证报告如实记录未修复门禁失败集）、F1118（DEBUG 文档自证已知缺陷与 state 漂移；正文与 genesis 大纲脱轨）、F1119（三子项目结构漂移）、F1163（时间戳编造倒挂）、F1164（ch35 唯一缺失 drafting-decisions）、F1165（上轮 F1311 的 117 项脱节复现）、F1166（污染 marker 滞留）、F1167（texture 配置脱节复现）、F1168（truth-index 停留 genesis 态）、F1169（patches 17 个回归例从未套用）、F1173（helper 可用性矛盾）、F1174（35 章 verdict 重试无账）

## 目标

1. **派发层根治**：沙箱写权/输出捕获模式修复，使 dispatch 产物不再需要"手动复制"类元叙述
2. **产物 lint 拦截**：新增产物污染检查（元叙述标记、手算分数自证、时间戳倒挂模式），进 G2/G7 或独立 lint
3. **存量清洗**：109 文件按层（audits/snapshots/staging/decisions/正文）清洗，快照二次嵌埋一并处理
4. 修复可信度重建：手算分数、编造时间戳等自证缺陷逐项以真实数据重算或标注废弃

## 任务分解

### T1 · 派发层根因修复（先断新增）
1. dispatch_helper 沙箱模式审计：写权受限路径改为"产物写临时区 + 派发层原子搬入 project_dir"（或等价捕获模式），LLM 输出不再含复制指令——具体方案对齐 #7/#21 的写路径语义（upsert/写安全），不另造第三套
2. 审计波体积治理（F1108）：审计报告默认聚合/去冗后落盘（与 2026-08-01 output-side-waste spec F9 同族，取其聚合层设计），快照内不再嵌埋审计全文

### T2 · 产物 lint
3. 新增 lint（建议挂 G2 产物校验或 tools/ 脚本 + CI）：(a) 元叙述标记模式（"手动复制"/"只读沙箱"等中英模式族）；(b) 分数自证模式（"手动计算"/"手算"与数值并存）；(c) 时间戳单调性检查（同产物链内）
4. lint 对现有 novel-output 全树跑出基线报告，作为 T3 清洗清单的机械来源（不靠人肉翻 109 文件）

### T3 · 存量清洗（按层分批）
5. audits 层（55 文件）：剥离元叙述块，保留审计实质内容；无法剥离的整文件重生成或标注 `contaminated: true` 移出生产树
6. snapshots 层（37 文件）：与 C19 协同——快照布局定稿后统一清洗（快照内嵌的审计全文随 T1.2 不再产生）
7. staging/decisions 层（16 文件）：未提交残留按 crash_recovery 语义处置（staging 生命周期属 C30，本处只清污染内容）
8. 正文 ch35（1 文件）：行级剥离元叙述；ch35 缺失 drafting-decisions（F1164）补生成
9. 手算分数（2 章 resonance + ch51 trend）：用 skill_utils 确定性 helper 重算覆盖（与 C7 接线协同），旧值留档对比
10. F1163/F1166/F1168/F1169/F1174：时间戳更正、marker 清除、truth-index 重生成、17 回归例套用或显式废弃、verdict 重试补账

### 批量清理（M 级成员）

## 验收标准（真实数据可复验）

1. 产物 lint 全树基线跑批：清洗后同一 lint 在 novel-output 上报告 0 命中（清洗前计数 109 文件留存于审计 run 记录，前后对照可复验）
2. 派发层修复后连续 2 次真实 dispatch（或回放 fixture 等价路径）产物 0 元叙述（人工抽查 + lint 双确认）

5. F1169 的 17 个 patches 回归例状态落账（applied/voided 二态，无第三态）

## 风险与回滚

- **风险**：清洗 109 文件动生产树——分批 PR + 每批前后 lint 计数对照；正文与快照层清洗前打 git tag 便于整体回退
- **风险**：派发层写权方案若选择"临时区搬入"，与 C11 并发纪律（safe_write/WRITE_SHARED）必须协同，避免新竞态
- **风险**：audit 聚合层改变审计报告结构，下游读者（G7、审计波读者技能）契约同步——登记进 C1 对账面
- **回滚**：派发层改动独立 PR；lint 带 flag 可关闭；清洗批次按 tag revert

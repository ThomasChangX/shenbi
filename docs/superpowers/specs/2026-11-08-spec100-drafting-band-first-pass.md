## 0. 根因假设

- **H1（主）**：场景预算与字数带在 drafting prompt 中脱钩——planning 产场景预算（场景数×场景粒度），drafting 按叙事自然长度写，两者未对齐到「逐场景目标字数」粒度（束7 反馈中「逐场景现值+缺口算术」生效恰证明该粒度有效，但只在事后反馈通道出现）。
- **H2**：模型自然长度偏短（中文叙事在 0.90 temperature+thinking low 下倾向收敛叙述），无首派目标字数显式锚。
- **H3（备择）**：带的下限 2800 对该题材场景结构（3 场景×900-1400）本就贴下沿——首派需 3×933 均值才达下限，无冗余空间（若成立→修 planning 场景预算分配而非 drafting）。

## 1. 任务分解

- **T0 数据面（半天，无实弹）**：束4/5/7 三窗首派 vs 终稿字数分布（逐场景）——欠带率/场景结构/反馈收敛派数统计；判定 H1/H3 主次（场景预算分配是否系统性贴下沿）。
- **T1 修复面（branch+PR，按 T0 择点）**：①drafting prompt 逐场景目标字数显式化（从 planning 场景预算派生，含「合计须入带」一句）；②（若 H3）planning SKILL 场景预算分配规则对齐带下限（3 场景制下目标均值 ≥950）；③反馈通道「逐场景现值」前移为首派前置输入。**字数带硬闸与 [2800,4000] 档位值不动**（平台承诺面）。
- **T2 离线验收**：既有 drafting 测试全绿+新断言（prompt 组装含逐场景目标字数行——fixtures 驱动）。
- **T3 实弹验收（搭卷二续跑窗）**：后续束窗 drafting **首派带内率 ≥50%** 且全程 0 熔断（疗效线；对照束7=首派 0% 带内+1 熔断）。

## 2. 验收

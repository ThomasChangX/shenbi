### F663 | compute_ttr 空输入早退分支输出 schema 不一致：缺 `content_ttr` 与 `total_chars` 键（正常路径两者恒有）→ 全标点/空语料的 ttr 报告缺键，下游 JSON 消费方 KeyError | 边界/schema 不一致 | P2（潜伏、低影响）

- 验证命令+输出：
  ```
  PYTHONPATH=src python3 -c "
  from shenbi.skill_utils.style_learning.compute_stats import compute_ttr
  print(compute_ttr(''))
  print(compute_ttr('。。。'))
  print(compute_ttr('你好世界'))
  "
  -> {'global_ttr': 0, 'sliding_ttr_mean': 0, 'sliding_ttr_std': 0}       # 缺 content_ttr/total_chars
  -> {'global_ttr': 0, 'sliding_ttr_mean': 0, 'sliding_ttr_std': 0}       # 同上
  -> {'global_ttr': 1.0, 'content_ttr': 1.0, 'sliding_ttr_mean': 1.0, 'sliding_ttr_std': 0, 'total_chars': 4}  # 正常 5 键
  ```
- 影响：潜伏、低影响——真实 56 章语料 combined 恒有正文（本轮实测 total_chars=424014），早退分支仅在空/全标点语料触发；属输出 schema 不一致（非语义错误，早退值本身正确为 0）。与 F619（CLI 缺参）同属"边界分支与主路径行为不一致"族。前 13 轮均未覆盖该分支（test_compute_stats.py 只测空列表/单值场景，未断言早退分支键集）。
- 建议方向：早退分支补齐 `content_ttr: 0` 与 `total_chars: 0`（或统一由主路径处理空 chars）；补单测（空文本/纯标点文本的 ttr 键集与正常文本一致）。

## 2. 新发现（F144）

F144 | phase_runner `load_state` 对 phase-state 文件无形状/类型校验：损坏或非 dict 的状态文件 → 未捕获 JSONDecodeError/KeyError/TypeError 裸 traceback，与其余命令的结构化错误信封不一致 | error | P2
- 证据: src/shenbi/phase_runner.py:36-40（`load_state`：`json.loads(state_file.read_text(...))` 无 try；返回 `cast(dict[str, Any], ...)` 不做形状断言；缺文件时静默回退 CREATED）；对比同文件 :139-146（SKILL.md 缺失 → emit ERROR 信封）、:281-289（scores 缺失 → emit ERROR 信封）、cmd_post_score :290-292 注释明示 "a malformed file must abort here rather than silently advancing state"（加载侧无对应守卫）
- 根因: 状态机"崩溃恢复"设计的持久化侧（save_state）有原子写保证，但加载侧（load_state）无对称校验；`cast(dict[str, Any], ...)` 是类型层声明而非运行时校验——文件内容为 `[]`/`"x"`/`{"foo":1}`/非法 JSON 时，首个 `state["state"]` 访问即抛 TypeError/KeyError/JSONDecodeError，六条命令（start/pre-skill/post-skill/pre-score/post-score/finalize 全部经 load_state 入口）以裸 traceback 崩溃而非结构化错误
- 验证命令+输出: `python3 - <<EOF`（模拟 load_state 三种坏输入）→ `[]` → `TypeError: list indices must be integers or slices, not str`；`{"phase": "genesis"}`（缺 state 键）→ `KeyError: 'state'`；`{not json` → `JSONDecodeError`（均为未捕获异常，无 emit_json 错误信封）
- 建议方向: `json.loads` 后增加形状断言（`isinstance(data, dict) and "state" in data`），失败 → emit_json `{"status": CommandStatus.ERROR, "error": "phase-state corrupt", ...}` + exit 1（与 :139-146/:281-289 信封一致）；与 F128/F132 一并形成"状态文件两侧（读写）对称校验"的修复组
- 严重度说明: 按决策表 P2"边界/错误处理缺陷 / bare 防御缺失"（与 F124/F129 的"坏输入 → 裸 traceback"同族且为同文件内唯一未设防的加载边界）；触发需状态文件损坏/外部篡改（safe_write 原子写正常不产生），若合并层认为触发面异常可议降 M，本复核按决策表定 P2

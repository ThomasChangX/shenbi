### F620 | `_check_linguistic_drift` 唯一调用点用宽泛 `except Exception` 吞掉 DriftEscalationError → "ESCALATE 暂停 pipeline" 契约在任何路径下永不生效 | error | P1
- 证据：`src/shenbi/pipeline/chapter_loop.py:2722-2727`（`try: _check_linguistic_drift(project_dir, chapter) / except Exception: log.warning("linguistic_drift_check_failed", exc_info=True)`）；`:2716` 注释 `# ── Linguistic drift check (non-blocking) ──`；`:529`（`class DriftEscalationError(Exception)`）；函数内 `:2031-2036`（`raise DriftEscalationError("Chapter {chapter}: system term density ... Pipeline paused for human review.")`）；全仓 `grep _check_linguistic_drift` → **唯一**生产调用点即 :2722。
- 根因：调用点与函数内契约自相矛盾——函数在 `severity == "ESCALATE"` 时 raise 以暂停 pipeline，但调用点捕获全部 Exception 并仅记 WARN（注释还宣称 non-blocking）。即使修复 F612（放开 is_drift 门控使 ESCALATE 可达），raise 也在调用点被吞 → "Pipeline paused for human review" 永不发生；唯一的 `except Exception` 还连带吞掉其他真实错误（如文件读错误、detect_drift 内部异常），全部静默降级为 WARN。
- 验证命令+输出：
  ```
  grep -rn "_check_linguistic_drift" src/ tests/ --include=*.py
  -> 仅 chapter_loop.py:2722 一处调用（+ def :1994 与 tests/coverage 静态页）
  代码精读 :2716-2727 + :529 + :2031-2036
  ```
- 建议方向：二选一并显式化——(a) 若 ESCALATE 应暂停：调用点按异常类型处理（捕获/放行 DriftEscalationError 到 pipeline 顶层暂停逻辑），或 (b) 若漂移检查确为 non-blocking：删除函数内 raise 并把"暂停"降级为审计记录，同时在计划文档标注。补单测：构造 is_drift=True + severity=ESCALATE 的 detect_drift 结果，断言调用点行为与文档一致。

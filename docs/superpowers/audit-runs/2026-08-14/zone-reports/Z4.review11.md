## 二、新发现（F491-F492）

### F491 | g4_worldbuilding 地点计数双重缺陷：`## 地点[：:]?` 可选冒号吞掉"## 地点构建汇总"汇总节 + numbered_loc 优先分支把任意 `## N.` 标题当地点数 → SKILL 模板合规输出误报 `G4.locations.count` FAIL | error | P2

- 证据: src/shenbi/gates/g4/worldbuilding.py:129-133（`location_headings = len(re.findall(r"## 地点[：:]?", loc_text))` —— 冒号可选，`## 地点构建汇总` 匹配 `## 地点` 前缀即计入；`numbered_loc = len(re.findall(r"## \d+\.\s+\S+", loc_text))` —— 计数**任意** H2 编号标题；`loc_count = numbered_loc if numbered_loc > 0 else location_headings`）。skills/shenbi-location-builder/SKILL.md:109（`## 地点：{name}` 每地点格式）与 :165-168（输出含 `## 地点构建汇总` 汇总节）。
- 根因: (a) `## 地点[：:]?` 的可选冒号使汇总节标题被计入地点数（5 真实地点 + 1 汇总 = 6 > 5 → 误报 FAIL）；(b) numbered 优先分支用全文件 `## N.` 标题数代替地点数，任何非地点编号标题（如 `## 1. 布局`）都会顶替真实计数。真实项目 `novel-output/xinghuo-ranqiong/world/locations.md` 恰好同时含 `## 1.`-`## 5.` 编号标题（5 个即地点数）而**偶然通过**（count=5，已实测），掩盖了该缺陷。
- 验证命令+输出: 构造 SKILL 模板合规输出（5 个 `## 地点：X` + `## 地点构建汇总`，无编号标题）→ `g4_worldbuilding([], None, '/tmp/locproj')` → `status: FAIL`，`must_fix: ['G4.locations.count:6']`（真实 5 地点被误计 6）；反向构造（2 个非地点编号标题 + 5 个 `## 地点：`）→ `loc_count: 2`（错误顶替）。
- 建议方向: `## 地点[：:]` 强制冒号（与 location_builder.py:40 一致，排除汇总节）；numbered 分支改为校验编号标题文本含"地点"语义或删除该优先分支；补"5 地点+汇总节 → PASS"与"非地点编号标题不干扰计数"用例。
- 严重度说明: 正常路径（SKILL 模板格式输出）可复现误报 FAIL，但真实项目当前因编号标题巧合而通过，故按 F434 同类（误报方向、宽松启发式）取 P2。

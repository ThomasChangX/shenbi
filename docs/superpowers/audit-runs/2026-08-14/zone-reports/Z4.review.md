## 二、新发现（F419-F430）

### F419 | G1.2 / G2.4 对合法非对象 JSON 崩溃（jload ValueError 未捕获） | error | P2
- 证据: src/shenbi/gates/g1.py:210-213（`jload(fp)` 在 `except (json.JSONDecodeError, OSError)` 内）；src/shenbi/gates/g2.py:169-172（同型）。`shared.jload`（shared.py:52-55）对合法但非 dict 的 JSON 抛 `ValueError`，两处 except 均未捕获。
- 根因: `json.JSONDecodeError` 是 `ValueError` 子类，但 `jload` 自抛的 `ValueError`（"expected JSON object, got list"）不在 except 元组内 → 传播到调用方，gate 崩溃、无 JSON 输出。
- 验证命令+输出: `.venv/bin/python -c "gate_G1('shenbi-x', ['list.json'])"`（list.json=`[1,2,3]`）→ `ValueError ...: expected JSON object, got list`；`gate_G2([list.json],'report')` 同崩。
- 建议方向: except 增加 `ValueError`（与 g5.py:38/g6.py:37 的写法对齐），非对象 JSON 应记 FAIL 而非崩溃；补数组/字符串 JSON 用例。

### F420 | G6 在 novel.json / genre-config.json 损坏时崩溃（无 try/except） | error | P2
- 证据: src/shenbi/gates/g6.py:49-51（`_nj = jload(str(nj))` 无保护）、:54-59（`jload(str(gc))` 无保护）。其余 G6 子检查（G6.0 等）均有 try/except。
- 根因: 配置读取未包防御分支；损坏配置 → JSONDecodeError/ValueError 直接传播 → `shenbi-validate G6 ...` 崩溃（对比 g0.py:206-207 同类读取有捕获）。
- 验证命令+输出: 构造 `novel.json='{invalid'` 后 `gate_G6('pipeline-x', d, d)` → `JSONDecodeError Expecting property name...`。
- 建议方向: 包 try/except 降级为默认 target_words/CHAPTER_WORD_FLOOR 或返回 FAIL JSON；补损坏配置用例。

### F421 | G_RECONCILE / G_DISPATCH / G_TRANSITION 对非对象 progress.json 崩溃 | error | P2
- 证据: src/shenbi/gates/g_reconcile.py:33（`progress = jload(str(pp))` 完全无 try）；g_dispatch.py:37-38 与 g_transition.py:38-39（`except (json.JSONDecodeError, OSError)` 缺 `ValueError`）。
- 根因: `jload` 对非 dict JSON 抛 `ValueError`；g_reconcile 无捕获、另两门漏捕获（g5.py:38 / g6.py:37 均含 ValueError，写法不一致）→ CLI 崩溃违反 JSON 契约。
- 验证命令+输出: progress.json=`[1,2,3]` → `gate_G_RECONCILE(d)`、`gate_G_DISPATCH('p1',d)`、`gate_G_TRANSITION('p1','p2',d)` 三者均 `ValueError: expected JSON object, got list`。
- 建议方向: 三处统一 `except (json.JSONDecodeError, OSError, ValueError)` 并返回 FAIL JSON。注：初审 F401 建议中已提及 test_g_reconcile.py:157-167 用 pytest.raises 钉死该崩溃——本 finding 将其独立编号并扩展到另外两门。

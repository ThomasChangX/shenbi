## 3. 新发现（F647-F648）

### F647 | records drift.py `by_id` 对重复 id / 缺失 id 静默塌缩：权威 YAML 中重复 hook id 只保留最后一条，派生表与"错误的那条"比较 → 漏报或误报 drift 且无任何告警 | 边界/数据视图损失 | P2

- 证据：`src/shenbi/records/drift.py:80`（`by_id: dict[str, dict[str, Any]] = {str(r.get("id")): r for r in yaml_records}` —— dict 推导，重复 id 后者覆盖前者；缺失 id 时 `str(None)="None"` 全部塌缩到同一键）。
- 根因：权威 YAML 记录源（parser 产出，可能由 LLM 写入）出现重复 id（同 hook 被重复记录）或缺失 id 时，`by_id` 静默丢记录——最后一条胜出，前一条从 drift 比较中消失。派生 md 表与"最后一条"一致时**漏报**（第一条的差异不可见）；与"第一条"一致时**误报**（对最后一条报假 drift）。与 F603（方向）、F616（非 dict 丢弃）、F641（布尔比较）均不同：本缺陷是**权威源内部重复导致的数据视图静默塌缩**，无任何日志/告警。
- 验证命令+输出：
  ```
  # 漏报：md 与最后一条重复记录一致 → drift 恒空，第一条（PLANTED）静默丢失
  detect_cross_section_drift([{'id':'H01','state':'PLANTED','type':'主线'},
                              {'id':'H01','state':'PLANTED','type':'支线'}],
                             {'H01': {'id':'H01','state':'PLANTED','type':'支线'}})
  -> []   # 权威源含冲突的两条记录，派生表只对齐后者，无 drift 信号
  # 误报：md 与第一条一致 → 对最后一条报假 drift
  detect_cross_section_drift(同上, {'H01': {'id':'H01','state':'PLANTED','type':'主线'}})
  -> ["drift: id=H01 key=type md='主线' != YAML='支线'"]
  # 缺失 id：str(None) 塌缩
  detect_cross_section_drift([{'id':None,'state':'PLANTED'},{'id':None,'state':'RELEVANT'}], {'None': {...}})
  -> 与"None"键比较（同上语义）
  ```
- 影响：判据 12 的 block-ship 安全网在重复 id 场景下给出错误信号（漏报=脏权威源通过 gate；误报=健康派生表被 block）。当前真实数据无 `## hooks` 结构（F637）→ 潜伏；一旦权威格式恢复（F637 修复方向 (a)），该缺陷即进入活动路径。消费链 write_audit.py:54-56 → record.py:24 `blocked = bool(violations) or bool(drift)`。
- 建议方向：`by_id` 构建时检测重复（`len(by_id) != len(yaml_records)` → log WARNING + 记重复 id 清单）或按 id 分组比较全部记录；缺失 id 的记录同样告警（与 F610/F616 的"脏数据不静默"修复同族）；补单测（重复 id / 缺失 id 两种输入）。

### F648 | compute_stats.compute_percentiles 小样本（n=2）百分位倒挂：P75/P95 取到最小值而 P50 取最大值（P75 < P50，数学上不可能） | 统计口径边界 | P2

- 证据：`src/shenbi/skill_utils/style_learning/compute_stats.py:99-104`（`"P75": values[max(0, int(n * 0.75) - 1)]`、`"P95": values[max(0, int(n * 0.95) - 1)]`——`int()` 截断 + `-1` 组合在 n=2 时把索引压到 0）；`:102`（`"P50": values[n // 2]` 对 n=2 取索引 1）。`compute_sentence_stats` :119 消费（n=2 即文本恰好 2 句）。
- 根因：n=2 时 `int(2*0.75)-1 = 0`、`int(2*0.95)-1 = 0` → P75=P95=values[0]（最小句长），而 P50=values[1]（最大句长）→ **P75 < P50 倒挂**。P50 修复（:100-102 注释）只对齐了中位数，未同步上分位公式的截断语义；对更大 n 该公式系统性低估上分位（n=10 时 P95=values[8] 实为 P90 档），但仅 n=2 出现严格倒挂（违反单调性，任何百分位定义都不允许）。
- 验证命令+输出：
  ```
  compute_percentiles([1, 2]) -> {'P25': 1, 'P50': 2, 'P75': 1, 'P95': 1}   # P75=P95 < P50
  compute_sentence_stats([('a',5),('b',10)]) -> P25=5, P50=10, P75=5, P95=5  # 报告中位数 10、P75 却 5
  n=3/4/5 复核：P75 >= P50 成立（仅 n=2 倒挂）
  tests/unit/skill_utils/test_compute_stats.py:73-83 只测空列表与单值，无 n=2 用例（倒挂未被测试锁定，也未被发现）
  ```
- 影响：compute_sentence_stats 是 style-learning 报告（skills/shenbi-style-learning/SKILL.md:51 强制调用）的句长统计入口；当语料（或未来 per-chapter 统计）恰好 2 句时，报告出现"中位数 10 但 P75=5"的数学不可能值，误导风格判断。真实 56 章语料 n=12218（实测 `sentence_length count: 12218`）不触发 → 潜伏；边界（极小语料/单章短片段）触发。
- 建议方向：百分位改用 nearest-rank（`values[max(0, min(n - 1, math.ceil(n * p) - 1))]`）或统一为 `values[min(n - 1, int(n * p))]` 并保证单调（P25 ≤ P50 ≤ P75 ≤ P95 用 `max(prev, ...)` 夹取）；补单测（n=2 的 P75 ≥ P50、n=1/2/3 边界 + 单调性断言）。

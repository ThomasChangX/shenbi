## 二、新发现（F537+）

### F537 | `_changed_top_keys` 的 `.get()` 把"缺失键"与"null 值键"归并为同一信号：OWNERSHIP field 文件新增 null 值键 / 删除 null 值键 → 键集变化零检测 → field 级审计静默放行 | 审计正确性 | **P2** | snapshot.py:73-75；ownership.py:114-119

**证据**：
- snapshot.py:73-75：`for k in set(a) | set(b): if a.get(k) != b.get(k): keys.add(k)` — dict.get 对"键缺失"与"键存在但值为 null"返回同一 None → 两者被判定相等。
- 实证：`_changed_top_keys('{"approval":"ok","version":1}', '{"approval":"ok","version":1,"x":null}')` → `()`（**新增键 x 不可见**）；反向（删除 null 值键）同样 `()`；对照 `{"x":1}` 新增 → `('x',)` 正常检测。
- 全链影响：`compute_file_change('genre-config.json', pre, post)` → `status=modified changed_top_keys=()` → `check_write_ownership('shenbi-genre-config', …)` → `violations=[]` — shenbi-genre-config 以 `{"evilKey": null}` 形式新增未授权键零拦截（实测输出见验证命令）。
- 与 F526（dict→list）/F534（broken JSON）同函数不同分支：F526 是 isinstance 非 dict 分支、F534 是 JSONDecodeError 分支、本 finding 是值比较分支的 null↔missing 归并——均为 field 级审计的"变更形态失明"。同族记录级（`_diff_records` snapshot.py:90 `pre_by[rid].get(k) != rec.get(k)`）：记录某字段从 null 变为缺失（或反之）同样不可见。
- 前五轮均未提及该分支。

**验证命令+输出**：
```
PYTHONPATH=src python3 -c "… _changed_top_keys …"
null add: ()        # {"x":null} 新增键零信号
null del: ()        # 删除 null 值键零信号
real add: ('x',)    # 非 null 值正常检测
→ compute_file_change('genre-config.json', '{"approval":"ok","version":1}',
  '{"approval":"ok","version":1,"evilKey":null}') → modified changed_top_keys=()
→ check_write_ownership('shenbi-genre-config', change) → violations: []
```

**根因**：field diff 以 `.get(k)`（缺键与 null 同值）而非"键存在性 + 值"双维比较；FileChange 无字段表达"null 值键的新增/删除"。

**建议方向**：`_changed_top_keys` 改为显式键存在性比较（`k in a`/`k in b` 判定增删，null 值视为真实值参与 `!=`），与 F526/F534 修复合并；补"null 值键新增/删除"测试。

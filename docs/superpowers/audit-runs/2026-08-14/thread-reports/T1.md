### T1-01 | pipeline 模式下 decisions.json 无任何门校验：G2 整门跳过 + G4 文件列表不含 .json → G4.dec 恒 SKIP "no files"，门恒 PASS | 校验洞（根因级） | **P1**

- 证据：
  - `src/shenbi/pipeline/executor.py:197-206`：`is_pipeline = (round_dir/"pipeline-state.json").exists()` → `g2_skipped_pipeline`（G2 整门不跑，含 G2.dec 分支）

  - `src/shenbi/gates/g4/generic.py:167-172`：composite 按扩展名分区 → `json_files=[]` → `g4_decisions([])` 走 `decisions_validator.py:120-121` `SKIP "no files"` → PASS
  - **真实 gate marker 实证**：`novel-output/xinghuo-ranqiong/gate-markers/G4-shenbi-chapter-drafting-generative.json` → `{"id":"G4.dec","s":"SKIP","r":"no files"}`，`files_checked:["chapters/chapter-56.md"]`；`G4-shenbi-chapter-revision-generative.json` → `files_checked:["chapters/chapter-55.md"]`
  - 产物面：`chapters/chapter-56-decisions.json` 为 invalid JSON 仍 PASS
- 根因：pipeline 重构（G2 按设计跳过、G4 文件列表只取主输出 .md）与 decisions 校验契约（AGENTS.md "G2 validates decisions.json as file_type=decisions" + "G4 validates schema + P2.5 rules"）未同步；composite 接线正确但**永远收不到 .json 文件**——校验器写对了、接线写对了、文件列表没给。

- 建议方向：`_resolve_g4_files` 改为返回该 skill 契约 writes/updates 的**全部**解析路径（或按 contract 输出推导），使 composite 的 json 分区实际收到 decisions.json；pipeline 模式下补一道 decisions 校验（G2.dec 或写路径 DecisionsDoc 前置校验二选一）。
- 交叉引用：**Z11-01 的根因答案**（Z11-01 悬置问题"若这些产物过过 G4，说明校验被绕过；若没过，说明 pipeline 落盘了失败产物"→ 两者皆非：G4 对 decisions 文件**从未被调用**，因为文件根本没进 G4 列表）。与 F469（revision composite 槽位反接）互补：F469 是"进了列表但走错 checker"，T1-01 是"根本没进列表"。

## 4. 结论摘要

- **新 finding 数：8**（T1-01~T1-08：P1×3、P2×4、M×1）
- 全链判定：decisions-sidecar 契约在**生产主路径（pipeline）处于"写入无校验、读取悬空、产物滞留"三态并存**——validator（DecisionsDoc）与文档本身实现正确，但 (a) G4 文件列表构造（chapter_loop._resolve_g4_files）从未把 decisions.json 送入校验器、(b) G2 在 pipeline 被整门跳过、(c) producer 模板与 prompt 不含 schema/P2.5 编码、(d) 写路径 clean-JSON 不做 schema 校验且 IDE 直写完全绕过、(e) context-composing 被移除后 consumer 读悬空、(f) plan/state-settling decisions 无契约 producer 且滞留 staging。T1-01 为 Z11-01 的根因答案（G4.dec 恒 SKIP "no files"——真实 gate marker 实证）。

## 七、findings

### T1301 · [P2] pytest-asyncio 声明于 dev group 但全仓零异步测试（休眠插件）

- **证据**：pyproject.toml:30 声明 `pytest-asyncio>=0.23.0`（锁 1.4.0）；pyproject:440 已配置 `asyncio_mode = "auto"`；但 tests/ 全仓 grep：`async def test_` 仅 1 处命中且为 **test_test_density.py:31 的 docstring 文本**（非代码），`@pytest.mark.asyncio` 0 命中，任何配置文件（ci.yml/justfile/.pre-commit）0 引用。
- **影响**：插件 + 配置项均为死配置；安装面 +1 包（含其依赖链），无行为贡献。
- **建议**：移除声明与 `asyncio_mode` 配置；若未来引入异步测试再按需加回。

### T1302 · [P2] pytest-ordering 声明但零使用，且 0.6（2019）无人维护

- **证据**：pyproject.toml:33 声明 `pytest-ordering>=0.6`（锁 0.6，2019-08 最后发布）；全仓 `@pytest.mark.order` / `--order-dependencies` 等 0 命中；CI/justfile/工具 0 引用。其 dist-info METADATA `License: UNKNOWN`（仅 classifier 标 MIT）。
- **影响**：与 pyproject:15 已处置 `patch` 的标准（"unmaintained since 2016，移除"）同根——本包同样停更且未使用，留在 dev group 无益且有元数据瑕疵。
- **建议**：移除声明并更新 uv.lock；测试顺序独立性已由 pytest-randomly 承担。

### T1303 · [P2] numpy 为核心依赖但其全部引用点仅在 Route B 可选路径执行

- **证据**：numpy 唯一引用 `truth_embed.py:185-200`（函数级 import）；`search_cosine` 唯一生产调用方 `context_assemble._search_route_b`（:143-160）以 `is_embed_available()`（sentence-transformers 已装）为前置闸门，未装时 :148-150 提前 return → **numpy 仅在 embeddings extra 场景执行**，而该场景 numpy 已被 sentence-transformers 链 transitive 带入。pyproject:14 注释自述用途即"Route B float32 cosine similarity"。
- **影响**：core 安装净增 numpy（~18MB wheel）而 core 运行时永不触达；与 pyproject:17"避免 core install 拉入大型 ML 依赖"的意图不一致（量级远小于 torch，属优化非错误）。
- **建议**：将 `numpy>=1.26.0` 从 `[project.dependencies]` 移入 `[project.optional-dependencies].embeddings`（`uv sync` 后 embeddings 安装面不变，core 减负）。

### T1304 · [P2] dev group 的 setuptools 无任何运行时消费者（冗余直接声明）

- **证据**：pyproject:48 `setuptools>=81.0.0`（锁 83.0.0）；全仓 src/tools/justfile/.pre-commit-config.yaml grep `pkg_resources|setuptools|importlib.metadata` = 0 命中；uv.lock 显示 torch 已 transitive 依赖 setuptools → dev 组声明对实际环境无增量。
- **影响**：声明冗余；dev group 语义漂移（无消费者），误导读者以为有工具依赖它。
- **建议**：删除该声明并 `uv lock` 更新（删除后 dev 环境包集合不变，因 torch 仍 transitive 提供）；若为历史 editable-install 兼容残留，已无必要（hatchling + uv）。

### T1305 · [M] plugins/master.json version=0.2.0 与 pyproject version=0.1.0 漂移，无同步机制

- **证据**：plugins/master.json:3 `"version": "0.2.0"`（PR-45 `3f8d768` 引入）vs pyproject.toml:3 `version = "0.1.0"`；`shenbi-generate-plugins` 生成 `.codex-plugin/plugin.json` 时原样透传 master.json 版本（generate.py:50），两源无校验/联动；codegen-idempotency CI 只查生成物新鲜度、不查版本一致性。
- **影响**：插件市场版本与框架版本两套计数，无记录说明 0.2.0 的语义（框架 0.1.0 的插件包为何 0.2.0）；未来发布易混淆。
- **建议**：master.json 增加 `framework_version` 独立字段或注释说明插件包版本策略；或在 generate.py 中校验/同步。

### T1306 · [M] pyproject.toml:11 pydantic 注释"P-1 不用；为 P0 schemas 准备"已过期

- **证据**：注释声称 pydantic 未被使用、仅为未来 schemas 预留；实际 pydantic 已是 contracts/schemas（9 模块）、contracts/skills（8 模块）、dispatch_helper.py、gates/g2.py、gates/g4 等 20+ 模块的核心依赖（见核实表）。
- **影响**：注释误导读者（"不用"的包实际是契约支柱一核心）；属于历史计划残留。
- **建议**：更新注释为实际用途（如 "P0 schemas 契约模型（contracts/schemas + skills）"）。

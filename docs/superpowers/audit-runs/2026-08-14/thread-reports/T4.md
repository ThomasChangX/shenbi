## 二、findings

### T401 | usage 载荷形状/类型脆弱：缺 total_tokens / None 值 / dict 形状 → AttributeError/TypeError 崩计量热路径（API 成功后、输出写盘前）→ 丢 LLM 输出 | P2 | dispatch_helper.py:1292-1294, 1326-1328；ledger.py:73-75

- **机制**：`_log_token_usage` 对 usage 的 `prompt_tokens`/`completion_tokens`/`total_tokens` 三属性全部裸访问（:1292-1294 日志 + :1326-1328 `+=` 累加）；`TokenLedger.record` 再裸 `int(usage.get(...,0))`（ledger.py:73-75）。调用点 `_dispatch_via_api:1561-1562/1617-1618` 无 try 包裹，且位于 `_write_parsed_outputs`（:1649）**之前** → 异常传播即丢本次已成功的 LLM 输出、该步失败。
- **实测（/tmp 沙箱复现，PYTHONPATH=src）**：
  - `SimpleNamespace(prompt_tokens=100, completion_tokens=50)`（缺 total_tokens）→ `AttributeError: ... no attribute 'total_tokens'`（崩在 :1294）
  - `total_tokens=None`（部分 OpenAI 兼容端点返回 `"total_tokens": null`）→ `TypeError: unsupported operand type(s) for +=: 'int' and 'NoneType'`（崩在 :1328）
  - dict 形状 usage → 静默 return（:1287 分支不匹配）→ **零落账无告警**（少计模式）
- **与既有 finding 边界**：F504 只覆盖 ledger.py:73-75 的 `int()` 强转 **ValueError**（字符串不可转）——`+=`/属性访问的 **AttributeError/TypeError**（dispatch_helper.py:1292-1294/:1326-1328）与 `int(None)`→**TypeError** 不在其列；F519 是写侧 OSError；F525/F533 是读侧。此为同一崩溃窗口（F519 同窗口）下的**独立异常机制**。
- **测试掩盖**：`tests/pipeline/test_dispatch_helper_ledger.py` 全部用三字段齐全的 SimpleNamespace（:17,57,76），不覆盖缺字段/None/字符串形状。
- **建议方向**：在 `_log_token_usage` 入口做 usage 形状归一化（`getattr(usage, k, 0) or 0` 兜底，dict/对象双兼容），与模块"must never crash the pipeline"契约（ledger.py:26-28）一致；补缺字段/None/dict 三形状测试。

### T402 | shenbi-cost 报告零自动化消费：账本数据 write-only，成本观测纯人工 CLI | P2 | report.py:38-96；run_pipeline.sh/tools/.github/justfile/active docs 0 命中

- **证据**：全仓非 archive/audit 文件 grep `shenbi-cost|render_report|token-ledger` → 仅 report.py 自身 + tests/unit/cost/test_report.py（CLI 直调）；run_pipeline.sh、tools/、.github/、justfile、docs/framework|architecture 均 0 命中。`shenbi-cost` 控制台脚本（pyproject:64）唯一消费方是人工命令行。
- **影响**：成本侧车（ledger + report）即便修好 F302 少计，也只是"人想看才看"的孤立 CLI；pipeline 内无任何成本信号（无每章/每 run 成本日志、无预算告警、无自动报告落盘）——output-side-waste spec 的"重试预算计量"承诺操作面无兑现面。
- **建议方向**：pipeline 收尾（closure COMPLETED）或每章 checkpoint 后自动调用 `render_report` 落盘 `cost/report.md`；或至少 `print_token_summary` 同步读 ledger 汇总（当前只打印内存 state.token_usage，见 T4 边界注 3）。

### T403 | parallel 接线 state 的聚合非原子性 + F505 联动：F302 修复方向（Z5.review4 建议"全部调用方传 state"）在并行波上会激活共享 dict 竞态与跨实例 append 交错 | P2（潜伏，修复时须处理） | parallel_dispatch.py:86-91；dispatch_helper.py:1314-1329

- **机制**：`_record_token_usage` 对共享 `state.token_usage[skill]` 的 4 处 `+=`（:1326-1329）与 `if skill_name not in ...` 初始化（:1314-1323）均为非原子 read-modify-write/check-then-act，且不经过 `state._lock`（state.py:183 的锁只保护 steps_done/audit_results 等，token_usage 路径未用）。当前 parallel 传 state=None 故未激活；一旦按 F302 修复方向把 state 传入 `dispatch_reviews_parallel`（ThreadPoolExecutor 8 线程），聚合进入多线程共享写。并行的 `TokenLedger(project_dir).record` 仍每线程新建实例 → F505（每实例锁无效）的 append 交错同时激活。
- **实测**：CPython GIL 下两轮微基准（8×2000 次 barrier 对齐 + 200 线程单次 init 竞态，switchinterval=1e-7）**均未复现丢计数**——GIL 下窗口极小，但机制成立（字节码级非原子；free-threaded 构建/换运行时即暴露）。
- **建议方向**：接线 parallel 时采用 state.py:510-523 的 single-writer 模式（线程内本地累加 dict，主线程合并）或对 token_usage 加锁；并同时解决 F505（进程级锁/filelock）。**F302 修复 PR 必须把 T401 的形状防御 + 本项 + F505 一并处理**，否则只补 state 传递会引入新竞态。

### T404 | iter_records/summarize 静默跳过损坏行，报告无跳过计数：成本报告把不完整账本当完整展示 | P2（低，观测面） | ledger.py:82-99, 101-141；report.py:40-45

- **机制**：`iter_records` 对 JSONDecodeError/TypeError/（F533 修复后）UnicodeDecodeError 行一律 `continue` 仅 WARN；`summarize` 聚合后 report 只展示 totals，无"已跳过 N 行"提示——账本被部分截断/损坏时报告显示完整成本实则偏低，且报告侧无任何信号（模块契约"skip 不崩"本身成立，此为契约之外的可见性缺口，非契约违反）。
- **影响**：成本归集路径的数据完整性在消费端不可见；F525/F533 修复后此缺口成为常态路径（更多行被跳过）。
- **建议方向**：`summarize()` 返回 `skipped` 计数，report 在 totals 旁附注"（N 行损坏跳过）"。

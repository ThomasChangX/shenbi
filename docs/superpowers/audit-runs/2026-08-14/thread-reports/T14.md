### T14-01 · [P1] 确定性助手"提示词级接线"零强制：5 个 skill_utils 助手只靠 SKILL.md 指令（"必须运行 / 禁止跳过"），无任何 G4/门校验助手是否执行——铁律 #2（prompt-only 守卫不够）系统性复发

- **证据**：grep 全 src/，`compute_stats`/`compute_pattern`/`recall_overdue_hooks`/`confidence`/`review_resonance.routing` 均无生产调用点（仅 `__init__/__main__` + tests）；`grep -rln "python -m shenbi.skill_utils" skills/` → 4 个 skill（style-learning:51、review-resonance:63-64、drift-guidance:51,58,85、snapshot-manage:161）；gates/g4/ 32 个 checker 无一校验"统计 JSON 存在/助手 CLI 已运行"（g4/style_learning 等不存在，g4 列表见 `src/shenbi/gates/g4/`）。
- **真实 run 佐证（跳过不是假设）**：`novel-output/xinghuo-ranqiong/style/style_profile.md` 头部 = `**生成方式**: 种子指纹（bootstrap）`、`样本章节数: 0`、生成时间 2026-07-16 —— **56 章完成后 style-profile 仍是 bootstrap**，`compute_stats.py` 从未在生产的 style-learning 中产生真实统计，即使 SKILL.md 声称"禁止跳过此步"。
- **影响**：确定性防线的执行依赖 LLM 自觉；LLM 跳过时（风格统计改为估算、路由改为自判）静默发生，无错误信号。与 F602/F629 同族：计划承诺的确定性防线"未接线/未强制"。
- **建议**：接线标准 = pipeline 在 dispatch 前运行确定性助手（或 G4 校验助手产物存在），SKILL.md 指令降级为文档；对 compute_stats 至少加"stats.json 必须存在"的 G4 检查。
- **与既有 finding 边界**：F602（baseline 零调用）是"代码层未接线"；本条是"提示词层未接线+无强制"，机制不同、同为 铁律 #2 模式。

### T14-02 · [P2] hook_planting 死线补全（F307 新面）：TRIGGER_STEPS 卷边界仍 dispatch LLM 版 shenbi-foreshadowing-plant（活跃路径），与 foreshadowing-resolve 同块双写 pending_hooks.md

- **payoff**：卷边界 plant 调用（~3-4 次/书）可被 hook_planting.py 确定性替代 = 每卷省 1 次 LLM 调用（100%/调用）+ 消除双写冲突；per-chapter 面已过时，不应再以"每章 1 调用"计。
- **建议**：卷边界分支改调 `plant_hooks_from_plan`（先修 id 正则），或删除 TRIGGER_STEPS 条目并显式声明 plant 职责归 lifecycle。

### T14-03 · [P1] style-learning 全章 glob pass-through：chapters/*.md 全量注入（56 章 510KB → 截断后仍 ~128K chars ≈ 74.7K tokens/次），LLM 实际只需 compute_stats 的 JSON

- **证据**：contract reads `chapters/*.md`（style-learning SKILL.md:9）→ `_resolve_read_path`（dispatch_helper.py:390-404）glob 展开全部 56 章；`_build_skill_prompt`（:563-641）对 510,491 chars > 128K budget 触发 `_budgeted_truncate`：56 个 chapter 文件全部命中 `_get_priority` 的 HIGH(1.0)（dispatch_helper.py:302-309 "chapter" 子串），128K budget 按权重均分 → **每章仅保留 ~2.2K 头部字符**（章节开头，对统计无意义），仍占满 ~74.7K tokens。而 SKILL.md:38,51 指示 LLM 自己跑 `python -m shenbi.skill_utils.style_learning`（从磁盘读全文算统计）——注入内容与统计计算完全冗余，且截断后的章节头**无法**支撑统计（强化 T14-01 的 bootstrap-forever）。
- **触发频率**：ch%12（12/24/36/48）+ 卷边界（15/35/55）+ closure step 9 + 自愈 ≈ 7-9 次/书。
- **payoff**：pipeline 侧运行 compute_stats → 注入 stats JSON（~2-5KB）+ 1-2 个样本段，每调用输入降 ~99%（~74.7K → ~1-3K tokens），全书 **~530-675K tokens** 纯 pass-through 消除（输入单价 $0.14/M ≈ $0.07-0.09/书，且输入聚焦改善散文质量）。不消除调用（散文半保留）。
- **建议**：SKILL reads 去掉 `chapters/*.md`；dispatch 前 pipeline 跑 compute_stats（复用 T14-01 的接线）；G4 校验 stats.json 存在。

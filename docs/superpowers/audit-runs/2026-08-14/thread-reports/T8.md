## 四、Task 3 — fixture 的"真实路径"（是否绕过生产代码）

1. **G0.9 门只校验路径前缀**（`g0_purity.py:33-38` 正则 `ref.startswith("tests/fixtures/")`），**不校验文件存在性、不校验内容真实性**。→ 19 个空目录（仅 .gitkeep）被 20+ scenario 当作输入引用，G0.9 全部 PASS（T806）。
2. **bug-hunt 植错测试的 evidence 文件大面积不存在**：62 个 bug-hunt expected-output 中 **60 个**引用不存在的证据文件（`drafts/chapter-N.md`、`config/platform-rules/qidian-fatigue-list.json`、`snapshots/chapter-030/manifest.json`、`import/analysis/01_parse.md…08_state.md`、`characters/protagonist.md` 等）→ 植错测试无法按剧本执行（agent 找不到证据文件），测试或空转或必然失败（T807）。
3. **scenario 声称的缺陷内容与 fixture 实际内容不符**（植错前提为假）：chapter-drafting bug-hunt 声称 `chapter-draft-example.md` "无 PRE_WRITE_CHECK、然而×4/不过×3/与此同时×2"——实测文件**有** PRE_WRITE_CHECK 且 然而×1/不过×1/与此同时×0；review-sensitivity 声称 `sensitive_words.txt` 含 傻逼/白痴/脑残——实测仅 台独/藏独/法轮功，且 chapter-draft-example.md 无"白痴"（T808）。
4. **review-arc-payoff scenario 建立在锚点自创 lore 上**：bug-hunt 引用 `hook-007（老周留下的半块黑石饼）`、声称 outline-example.md "lists arc_beats"——实测 outline-example.md 无 `arc_beats`、truth-pending_hooks.md 只有 `hook-ch1-001..003`，"老周/黑石饼"仅存在于 calibration 锚点（手写）→ scenario 与 fixture 断链（T809）。
5. 生产代码侧的 fixture 消费是真实路径（非绕过）：`g6.py:408` 读 sensitive_words.txt（G6.12）、`scripts/lint_contract_fields.py` 读 EXAMPLE_FIXTURES、records parser 测试读 truth-pending_hooks.md。**问题不在"绕过生产代码"，而在"生产代码/门禁把自洽的假 fixture 当真实基准"**（T302 已述 lint 闭环；本线程补充：G0.14 把 27 个手写锚点哈希锁进门禁、G6.12 用 3 词敏感词表扫描）。

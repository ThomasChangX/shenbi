### T1401 | style-learning 统计半：全章 glob pass-through 消除 | 候选评估 | P1
- **现状**: `TRIGGER_STEPS` ch%12 + 卷界两处 + closure step 9（triggers.py:220-224,256-259；closure.py:108-112）dispatch LLM。frontmatter `reads: chapters/*.md`（skills/shenbi-style-learning/SKILL.md:7-13）→ dispatcher 将全量 56 章（实测 269,085 tok raw）注入 prompt，经 128K chars 预算截断后仍 ≈ **74.7K tok/次**。SKILL.md:51 指令"第一步必须运行 `python -m shenbi.skill_utils.style_learning`…禁止跳过"——**纯 prompt 级，无程序强制**（helper 396 行已存在且有测试）。
- **替代方案**: pipeline 在 dispatch 前代码级运行 compute_stats，prompt 只注入 stats JSON（~3-5K tok）+ 最近 2-3 章原文样本（散文半需要感受）；契约 reads 从 `chapters/*.md` 收缩为采样。先例形态：escalation/check.py 的代码接线（chapter_loop.py:1029）。
- **payoff**: (74.7K − ~5K) × 7-9 次/书 ≈ **490-620K tokens/书**（现行真实浪费，全书最大单点）。风险低（统计半有 433 行测试先例）；实现成本低（run_triggered_skills 前置 hook + reads 调整 + G4 契约同步）。顺带消除 F867 类模板漂移（11 节表格可确定性渲染）。
- **优先级依据**: 唯一"每 12 章 × 全量章节注入"的现行浪费，spec §2 "计数/tally 100%" 判据直接命中。

### T1440 | hook_planting 确定性替换是死代码，plant 三个活跃面仍 LLM dispatch | 优化 | P2
- **证据**: `chapter_loop.py:2778-2790` 的 `if step.skill == "shenbi-foreshadowing-plant": plant_hooks_from_plan(...)` 替换 handler 位于章节步执行器内，但 plant 已不在 `CHAPTER_STEPS`（:124 注释"Deprecated skills removed: foreshadowing-plant…"）→ handler 永不命中。活跃 LLM 路径三处：① `triggers.py:290-295` TRIGGER_STEPS 卷界 expand 项，经 `run_triggered_skills` :534 `dispatch_skill(step.skill, …)` 直发 LLM；② `genesis.py:70` GENESIS_STEPS step 9（genesis 模式）——台账 F887（P1）已立此面；③ closure 无 plant 面。
- **验证**: `grep -n "shenbi-foreshadowing-plant" src/shenbi/pipeline/chapter_loop.py` → 仅 :124（注释）与 :2779（死 handler）；`grep -n "foreshadowing-plant" src/shenbi/pipeline/triggers.py` → :290（TRIGGER_STEPS）。

### T1441 | anti-ai 检查清单与 G4 确定性检查构成双重体系：LLM 每章重算 G4 已算过的计数，且两套阈值不一致 | 优化 | P2

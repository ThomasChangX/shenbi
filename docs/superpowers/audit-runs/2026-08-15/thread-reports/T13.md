### T1301 | D1⑨ 漏洞审计检查对象错位：uvx pip-audit 审计的是临时环境 29 包而非项目依赖集，基线"无漏洞"结论无效 | audit-validity | P1

- **证据**：复现 `uvx pip-audit --format json`（/tmp/t13/uvx-audit-raw.json）→ JSON `dependencies` 数组恰为 pip-audit 自身临时环境 29 包（pip-audit 2.10.1、boolean-py、cachecontrol、rich……），0 个项目依赖；d1-09-pip-audit.log 的 "Installed 29 packages" 与此吻合。正确口径重审见域 1 表（131/21/132/157）。
- **根因**：pip-audit 无参数时审计"当前环境"；uvx 的当前环境是其临时层。D1 把工具可运行等价于检查已执行。
- **验证**：四份正确口径审计（含 .venv 实装、与 CI 同法）+ JSON 名单比对。
- **影响**：d1-baseline.md ⑨ 记载的 "No known vulnerabilities found" 属未执行的保证（false assurance）；若漏洞在 prod/dev 面将被同样漏过。本轮补审证明 prod+dev+实装面确实 0 漏洞，但 docs 组确有 1 项（T1302）——恰演示了该类错误的真实后果。
- **建议方向**：基线勘误（⑨ 结论改为引用本轮四口径结果）；审计协议固化正确命令（`uv run pip-audit` 或 export+pip-audit -r），禁止 `uvx pip-audit` 无参形式。

### T1302 | pymdown-extensions 11.0 已知 ReDoS 漏洞（PYSEC-2026-3654 / GHSA-gm37-52c6-37mw / CVE-2026-67422，修复版本 11.0.1） | security | P2

- **证据**：`pip-audit -r req-devdocs.txt`（docs 组口径）→ `pymdown-extensions 11.0: PYSEC-2026-3654, fix_versions=["11.0.1"]`；OSV query 确认影响区间 `introduced:0 → fixed:11.0.1`，advisory 修改于 2026-08-11（4 天前）。pyproject:54 声明 `>=11.0`，锁 11.0。
- **可达性裁决（逐条核实）**：漏洞为 caret/tilde/betterem/magiclink 四个 inline processor 的指数回溯 ReDoS（默认配置即触发，CVSS 3.1 提案 7.5）。本项目 mkdocs.yml `markdown_extensions` 仅启用 `admonition`、`attr_list`、`pymdownx.superfences`（mkdocs.yml:34-41）——**四个受影响扩展均未启用**，未用 pymdownx.extra（其捆绑 betterem）；docs.yml 虽在 `pull_request` 上构建不可信 PR 内容（docs.yml:5），但渲染路径不触达受影响 regex。故按 §8.1 表列 **P2（不可达已知漏洞，dev-only 工具链）**。
- **根因**：锁 11.0 早于 11.0.1 修复发布；且所有既有安全门都看不到它（T1303）。
- **验证**：审计 JSON + OSV API + mkdocs.yml 扩展清单比对。
- **影响**：若未来启用 caret/tilde/betterem/magiclink（Material 常见推荐配置）或 pymdownx.extra，fork PR 中一行 <50 字节 markdown 即可挂死 docs 构建 worker（docs.yml 对 pull_request 开放）。
- **建议方向**：`uv lock --upgrade-package pymdown-extensions`（约束 `>=11.0` 无需改；11.0.1 直接满足）；dependabot（uv direct-only weekly）本周内亦会覆盖到它。

### T1303 | CI 安全审计与 SBOM 系统性排除 docs 组：mkdocs 栈 26 包在 Security 门和发布 SBOM 之外 | security-coverage | P1

- **证据**：security.yml:13 `uv sync --frozen --group dev` → :14 `uv run pip-audit`、:15 `cyclonedx-py environment -o sbom.cdx.json`；release.yml:16 同范围 SBOM。docs 组 26 个包（mkdocs-material、pymdown-extensions、markdown、pillow、cairosvg……，全清单见 /tmp/t13 比对）不在该环境中 → **不被 pip-audit 审计、不进 SBOM**。`uv export --frozen` 默认同样只含 prod+dev（本轮实测 154 pin 无 mkdocs）。T1302 正是从此缺口漏过且 Security CI 保持绿。
- **根因**：audit/SBOM 与 docs 构建各自 sync 不同 group，安全门范围从未对齐"声明依赖全集"。
- **验证**：三 workflow 逐行比对 + export/pip-audit 四口径实验（docs 组独有包逐一列出）。
- **影响**：Security workflow 的绿徽章对 docs 组是 false green（当前已实际含 1 项已知 CVE）；SBOM 供应链合规面缺 26 包。
- **建议方向**：security.yml 审计步骤改 `--all-groups`（或审计改用 `uv export --frozen | pip-audit -r -` 覆盖锁全集）；release SBOM 若有意只反映运行时面，则在 SBOM 文档中声明范围，审计与 SBOM 分离处置。

### T1304 | GPL 家族许可证混入 dev 工具链（yamllint GPL-3.0-or-later 直接依赖、chardet LGPL 传递），上轮"无 GPL"结论需修正 | license | P2

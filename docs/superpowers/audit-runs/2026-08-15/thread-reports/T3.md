## 四、Findings

### T301 | G1 `check_fields_exist` 是从未被调用的死函数：字段漂移前置预警通道整体缺失 | dead-wire | P2
- **证据**：`grep -rn check_fields_exist src tests` → 定义 g1.py:102，调用仅 tests/unit/gates/test_g1_fields.py:17,28,38,46 与 tests/unit/pipeline/test_dispatch_helper.py:346；`gate_G1`（g1.py:147-291）体内无调用。dispatch_helper.py:1211-1214 注释："so skills that read ... find their H2 headings present on first run instead of tripping G1 ``check_fields_exist``"——注释承诺的 G1 检查不存在于 G1。
- **根因**：G1 gate 编排（G1.0-G1.6）从未接入该 helper；`fields_map` 参数也无任何生产构造方。
- **验证**：静态 grep（上述）+ gate_G1 全文复读。
- **影响面**：AGENTS.md 契约下"声明字段漂移"本应有 WARN-before-LLM 通道；该通道死线使 54% 零命中漂移（F239/本轮普查）在 CI 与运行时双重不可见。修复 F224（接线过滤）若无此预警，作者将持续无感知。
- **建议方向**：在 gate_G1 增加 G1.7（WARN 级）：由 `load_contract(skill)["read_fields"]` 构造 fields_map 调用 check_fields_exist，非阻塞输出到 gate report。
- **与 F224 边界**：F224 证据句提及 "check_fields_exist 生产调用方 grep 零命中"，但仅作旁证；本条将其单列为独立 dead-wire（F224 修复不自动修复本条）。

### T302 | fields.py 声称已统一三处分歧匹配语义，check_fields_exist 仍是另一套字面比较 | error/docs 漂移 | M
- **证据**：fields.py:1-2 "Replaces 3 divergent matching semantics: extract_h2_sections (exact), check_fields_exist (exact), lint normalize (lower)" vs g1.py:127-131 `actual.add(line[3:].strip())` + `set(fields) - actual`——未 import/未使用 `match_field`（无 NFKC/零宽/全角归一）。
- **根因**：统一只落在 filter_to_fields；check_fields_exist 未迁移。
- **验证**：两文件对照（行号如上）。
- **影响面**：潜伏（T301 死线掩盖）。若按 T301 建议接线，同一声明-文件对会在 G1 报 missing、在过滤时命中（或反之），预警与过滤互相矛盾。
- **建议方向**：T301 接线时同步改用 `match_field`。

### T303 | AGENTS.md "Field-Level Reads" 示例字段名对一切真实文件零命中——文档示例自身是漂移源 | docs 漂移 | P2
- **证据**：AGENTS.md:84 `fields: [主角状态, 当前世界局势, 活跃线索]`；skills/shenbi-chapter-planning/SKILL.md:8-10 与 skills/shenbi-review-continuity/SKILL.md:10-12 逐字相同；真实文件 novel-output/xinghuo-ranqiong/truth/current_state.md 的 H2 为 系统演化阶段/参数当前位置/进行中的情节线/世界状态变化（第56章）；tests/fixtures/truth-current_state.md 亦无此三节。
- **根因**：示例写作时未对齐任何 producer 输出；两个技能的声明照抄文档例句。
- **验证**：census4 输出（两条 entry 均 0/3）+ 三处文件 grep。
- **影响面**：文档教读者写出注定零命中的声明；即便修复 F224+T301，跟随文档的后续声明仍会批量落入 escape hatch 全文件回退。
- **建议方向**：示例改为对齐真实 producer 节名（或显式注明"节名必须与写方 SKILL.md 固定的 H2 一致"），并与 T304 的写方节名 schema 联动。

### T304 | 模板自愈（D21）只活到第一次 replace 写：写方技能无节名 schema，声明侧 54% 零命中的机制根因 | 漏报/机制 | P2
- **证据**：(a) 实跑 `_collect_declared_truth_fields()` → `current_state.md -> ['主角状态','当前世界局势','活跃线索']`、`chapter_summaries.md -> ['已完成章节']`（播种内容=声明 union）；(b) 真实 current_state.md frontmatter `filled_by: shenbi-state-settling`，节名与播种零交集；(c) shenbi-state-settling/SKILL.md 的 current_state 写作规范（replace-mode，:56）未固定任何 H2 节名表；(d) `_init_truth_templates` 只在文件不存在时播种（dispatch_helper.py:1264-1265 `if tp.exists(): continue`）。
- **根因**：Layer B 只有读侧声明，没有写侧节名契约；模板播种被首个 replace 写覆盖后永久失效。
- **验证**：/tmp/t3x/census4.py 全量统计 + 上述实跑与文件复读。
- **影响面**：F239 的 19 条零命中中，md 侧 19/26 的直接机制；F224 单独修复会让这 19 条全部走 escape hatch 全文件回退 + WARN 刷屏（与 Z2-review-r3 对 F239 的修复顺序警告一致，本条提供其机制证明）。
- **建议方向**：写方技能契约固定 H2 节名表（或 G4 校验写方输出的 H2 ⊇ 读方声明 union），先于/同步于 F224 接线。
- **与 F239 边界**：F239 = 统计事实（19/35 零命中）；T304 = 机制根因（模板自愈被摧毁 + 写方无 schema）+ 分维度扩展（md 28% vs json 100%）。

### T305 | filter_to_fields 对非 md/json 扩展名静默直通（matched=True、无 WARN、不过滤） | error/边界 | M
- **证据**：fields.py:91 `return text, True`；实测 `.txt`/`.yaml` 带声明 fields → `[TXT passthrough] matched=True WARN=False`、`[YAML passthrough] matched=True WARN=False`，全文件原样返回。
- **影响面**：当前普查 0 例非 md/json 声明（35 条全为 .md/.json），纯潜伏；但契约句 "filters file content to only declared fields" 对该分支静默失效，一旦未来声明 .yaml/.txt 即无声违约。
- **建议方向**：非 md/json 且 fields 非空时 log.warning（或 loader 拒绝非 md/json 的 fields 声明）。

### T306 | 注入环无过滤标注：`<document>` 注入不区分全文件与过滤子集 | 设计缺口 | M
- **证据**：dispatch_helper.py:741-748，`input_texts` 逐条以 `<document name="...">` 注入 user_prompt，无任何"已按 fields 过滤/已回退全文件"标注；:605 调用点丢弃 `_matched` 标志（F201 已记丢弃行为，本条补注入面语义）。
- **影响面**：当前 0（R3 死线）；F224 修复后，LLM 会把过滤子集当作文件全部内容，基于"不存在=事实不存在"推理，可能产生误判（例如以为某 truth 文件没有某节而重建之）。
- **建议方向**：修复 F224 时在 document 标注 `filtered_fields="..."` / `fallback="full"`。

### T307 | T1 dispatch 入口（shenbi-dispatch → codex exec）无任何 reads 注入：Layer B 在该面结构性缺失 | 漏报 | P2
- **证据**：dispatch_helper.py:1911 `_run_cmd = ["uv","run","shenbi-dispatch",skill,test_type,rd,prompt]`（fallback 路径）；dispatcher/cli.py:29 → executor.dispatch（executor.py:163-229）→ modes/codex.py:61-66 `subprocess.run(["codex","exec","-C",str(round_dir),"-o",... ,prompt])`——prompt 为原始任务串，reads 文件内容由子代理自行读取，全程不经 `_build_skill_prompt`、更无 filter_to_fields。
- **验证**：executor.py 与 modes/codex.py 全文复读（codex.py 117 行内仅 2 处 read_text，均为 progress/raw 输出）。
- **影响面**：AGENTS.md "Key Commands" 将 `shenbi-dispatch` 列为主入口之一；契约句 "The dispatcher filters file content ... before the LLM sees it" 在该入口结构性不成立（不是死代码，是根本无注入）。T1 测试面因此永远测试不到 Layer B（与 Z2-review-r1 "集成测试缺失是 F224 成因"互证——T1 面连可测的接线都没有）。
- **与 F224 边界**：F224 = fields.py 唯一调用点死代码（pipeline 面）；T307 = 另一 documented dispatch 面结构性无过滤。互补不重复。
- **建议方向**：T1 codex 路径复用 `_build_skill_prompt` 的 user_prompt（或至少在 prompt 中注入契约 reads 清单），否则在 AGENTS.md 明示 Layer B 仅适用于 pipeline 派发。

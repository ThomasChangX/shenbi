## 4. Findings

### T701 | upsert_markdown_row dict 形态整文件结构坍缩：frontmatter/H2/表格/散文全灭 + 表格强转 bullet 致表格读者全盲 | error | P1
- 证据：/tmp/t7x B1、B2-redo 实测；truth_io.py:143-165（`_read_truth_rows` 只抽行）+ 189-191（body 从 `# 标题` 重建）。B2-redo：`parse_trend` 读行 2→0。
- 根因：`_upsert_markdown_bullet` 把"行集合"当作文件全部内容重写；docstring 对 str 形态承诺的 "Preserves headers and non-table content"（truth_io.py:206）在 dict 形态下完全不成立，而 `write_truth_file` 把两种形态归入同一 mode。
- 验证：B1（种子形态文件一次 upsert 后 update_mode/主角情感线 H2/prose 全部消失）；B2-redo（表头销毁后 compute_drift.parse_trend 返回 0 行，escalation_bridge.parse_resonance_scores 同理按 `\|` 行读）。
- 影响面：`_TRUTH_FILE_TITLES`（dispatch_helper.py:1215-1220）为 emotional_arcs.md / chapter_summaries.md 声明的正是此 mode + `_init_truth_templates` 按消费者 fields 种子的 H2 结构——第一个 dict upsert 即清零；下游表格解析器（drift 检测、escalation floor）静默变盲。
- 建议方向：dict 形态要么改为在原文件定位 key 行做行级替换（保结构），要么显式拒绝写含 frontmatter/多节文件（fail-loud）；至少 mode 文档与两形态行为对齐。
- 边界：F360/F828 是 LLM 整文件覆写（W5 路由层）；本条是 Python 原语层**带键正确调用下**仍毁文件，独立成立。

### T702 | 表行键提取 = 首格首个非空白 token：含空格/CJK 键整族互删 | error | P1
- 证据：/tmp/t7x A1/A1b 实测；truth_io.py:209/219 `re.match(r"\|\s*(\S+)", line)`。A1b：`| 第 1 章 |`+`| 第 2 章 |` 两行被 upsert `| 第 3 章 |` 全部删除。
- 根因：键取 `\S+` 首 token 而非首单元格全文；含空格键（CJK 章标、LLM 手写行）token 相同 → 同键误判 → 旧行整族 `continue` 跳过。
- 验证：A1/A1b/A1-prod（良构 `Ch{N}` 单 token 行不触发——误删需行首 token 碰撞，LLM 手写行格式漂移即中招）。
- 影响面：resonance_trend.md 默认流由 LLM 整文件重写（F360），行格式不受 Python 构造器约束；一旦任何带空格键行入库，后续 upsert 触发静默批量删行。
- 建议方向：键改为首单元格全文（`r"\|\s*([^|]*?)\s*\|"` 首格），或沿用 `key_name` 做列定位。

### T703 | _upsert_by_key 静默丢弃无键**新**记录（与既有无键记录保留策略不对称） | error | P1
- 证据：/tmp/t7x C1 实测；truth_io.py:264-269（新记录循环无 else 分支）vs 260-263（既有无键记录 `order.insert(0,...)` 保留）。
- 根因：两个循环对"缺 key_field"处理不对称——旧的保、新的丢，且无日志无异常。
- 验证：`_upsert_by_key([], [{"id":"a"},{"noid":True}], "id")` → `[{'id':'a'}]`。
- 影响面：upsert_yaml 是 pending_hooks 类结构化文件的契约 mode；LLM 输出一条缺 id 的记录会被无声蒸发，调用方以为已落盘。
- 建议方向：新记录缺键 raise ValueError（与 upsert_yaml 缺 key_field 的 fail-loud 一致），或保留并 WARN。
- 边界：当前 upsert_yaml 零生产调用（W4 死），严重度按"键冲突处理错误"定 P1（原语契约层），接线时即爆。

### T704 | 键提取边界族：空首格键提取为字面 "\|" 且多个空键行互相覆灭；无空格首格键粘连管道符致同键重复；非表 new_row 裸 append 无去重（双跑重复） | error | P2
- 证据：/tmp/t7x A2/A3/A4；truth_io.py:209-213（空格被 `\s*` 吞后 `\S+` 匹配到 `\|`）、211-212（非表行 `return existing.rstrip()+"\n"+new_row`）。
- 根因：正则不校验单元格边界；非表行回退为无键 append。
- 验证：A2（val-x 被 val-y 覆灭）、A3（`|Ch1|` 与 `| Ch1 |` 双行并存）、A4（双跑 2 份）。
- 影响面：均为边界输入；生产唯一调用点传良构行。归 P2 边界缺陷。
- 建议方向：空键/非表行 fail-loud 或 WARN；键提取用单元格切分而非 token 正则（与 T702 一并修）。

### T705 | dict upsert 值含换行 → 渲染行分裂，下次读取静默丢数据 | error | P2
- 证据：/tmp/t7x B3 实测；truth_io.py:187（`f"{k}={v}"` 直接内插）+ 190（按行 join）。
- 验证：`{"chapter":"Ch1","note":"line1\nline2"}` → 文件两行，`_read_truth_rows` 只回 `{'Ch1': 'note=line1'}`。
- 影响面：LLM/技能生成的 dict 值含换行并非罕见；丢 silently。
- 建议方向：值序列化前 `\\n` 转义或校验拒绝。

### T706 | YAML 解析失败 → 记录集回退 [] → 下一次 upsert/append 整文件坍缩重写（truth_io 与 hook_planting 同根因；后者为生产活路径） | error | P2
- 证据：/tmp/t7x C4、E1 实测；truth_io.py:243-245（`except → log.warning → return []`）+ 136-139（[] 合并后全量重写）；hook_planting.py:243-244（`except Exception → warning`，existing_hooks 保持 []）+ 261-269（用 [] + 新钩子重建全文件）。

## 6. 总结

- 矩阵规模：**16 个写点 × 6 原语类**（create_or_overwrite / upsert(str) / upsert(dict) / upsert_yaml / append_dedup / safe_write 直写 / staging 拷贝 / snapshot 恢复 / 裸 append，归并为任务指定的 6 类）。
- 原语幂等率：同输入双跑幂等 **12/13 实现写点成立**（唯一例外 W13 裸 append）；但**键唯一性合格仅 5/13**——upsert 三形态（W2/W3/W4）与 append_dedup 活实现（W9）全部存在键或解析回退缺陷；3 个 upsert 原语生产 0 调用，append_dedup 契约 0 实现（grep 一次确认：src 中仅 dispatch_helper.py:1072/1074/1178 三处注释，无代码分支）。
- CN3 回归：22 个 /tmp 实测用例（A1-A7/B1-B5/C1-C5/D1/E1-E2），复现 9 类键提取/序列化缺陷，其中 2 类整行/整文件级数据丢失（A1b CJK 键族删、B1 结构坍缩）。
- 新增 findings：**13 条（T701-T713）—— P1×3（T701 结构坍缩、T702 token 键误删、T703 无键新记录静默丢弃）、P2×8（T704/T705/T706/T707/T708/T709/T710/T711）、M×2（T712/T713）**。
- 一句话结论：truth 写路径的原子性（safe_write）是扎实的，幂等性在"同输入"意义上普遍成立；系统性风险集中在**键的唯一性与解析失败的回退策略**，以及"有键原语死线、活路径无键"的接线倒挂（F360 的机制层根因），外加恢复链整体死线（T710）使一切覆写事故不可逆。

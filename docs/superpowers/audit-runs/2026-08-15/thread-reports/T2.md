## 二、Findings 详情

### T206 | "Auto-generated" 契约模型 worldbuilding.py 无生成器且手改零检测——"frontmatter 是唯一编辑面"声明的实测反例 | error | P2

**证据**
1. `src/shenbi/contracts/skills/worldbuilding.py:1` 头部声称 `"""Auto-generated minimal contract model for shenbi-worldbuilding."""`，第 8-9 行携带 `kind: str = Field(default="artifact")`——kind 事实的第二定义处。全仓 grep 该字符串：除 `contracts/skills/` 自身外零命中（无任何生成器）；git 历史该文件仅由 commit `76662a5`（"contract single-source architecture + production wiring (#8)"）一次性创建，此后无生成方提交。
2. CI 幂等门范围（`.github/workflows/ci.yml:86-89`）：`git diff --exit-code -- tests/tiers/deps.json docs/framework/ skills/ .codex-plugin/`——**不含 `src/shenbi/contracts/skills/`**。
3. **变异实验（/tmp/t2x/clone 内，已还原）**：将 kind default `artifact→ephemeral` 后 commit，依次运行 CI 三个生成器——`shenbi-sync-contracts` exit 0、`generate_autocheck_docs` 输出 "all up to date"、`shenbi-generate-plugins` exit 0——`git diff --exit-code`（CI 全范围）**exit 0，未检测**；`git status` 仅显示被改的模型文件本身。对照实验：commit 手改 SKILL.md body 数据契约视图 → sync 再生 → CI diff **exit 1，检出**（证明检测机制本身工作，唯独模型文件在盲区）。
4. 消费面：`REGISTRY`（`contracts/registry.py:41` 自动发现）的生产消费者仅 `tools/generate_autocheck_docs.py` 与测试；`src/shenbi/gates/g4/worldbuilding.py` 是不引用该模型的私有 checker（extends 2026-08-14 F201 的 dead-wire 家族：该 finding 立案 3 技能，本条补 worldbuilding 与 score_arc/volume/stratum 三评分共享模型）。

**根因**：生成物声称 "Auto-generated" 但生成器不存在于仓库（一次性产物）；幂等门只覆盖 sync-contracts/autocheck/plugins 三生成器管辖的路径。
**验证**：变异实验双向对照（如上）；`grep -rn "Auto-generated minimal contract model" --include=*.py` 仅命中文件自身。
**影响面**：唯一编辑面声明（legacy.py:7-10）在 S4 维度不可执行——kind 字段、模型字段集（AUTO-CHECK 渲染只含常量/公式/computed/validator 名，**不含普通字段与 kind**）手改后 CI 全绿静默合入。
**建议方向**：三选一——(a) 删除 worldbuilding.py 的 kind 冗余字段使 S4 不再复制 kind 事实；(b) 为 `contracts/skills/` 提供真生成器并入 CI diff 范围；(c) 明确改标注为手写文件并删除 "Auto-generated" 措辞。

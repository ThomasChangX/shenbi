## Findings

### T1101 | 压力测试无可执行形态（纯 prompt 文档，零 harness） | 可测性缺陷 | P2

**证据**:
```
ls tests/pressure-tests/          # → prompts/ 仅目录
ls tests/pressure-tests/prompts/  # → .gitkeep + 6 个 md（audit-skipping / chapter-writing /
                                  #    foreshadowing-fatigue / import-shortcut / snapshot-skip / state-drift）
grep -rn "pressure" justfile .github/workflows/   # → 零引用
pyproject norecursedirs           # → "tests/pressure-tests" 被 pytest 排除
```
prompt 内容评估（读了全部 6 个中的 2 个全文 + 其余标题）：形态为"你是 AI agent + 压力情境 + 期望的 Agent 行为"，且前置条件要求**手动**搭建最小小说项目（如 chapter-writing-pressure.md 要求手工创建 truth/、characters/ 等）。可执行性判定：每个 prompt 都是 T1 dispatch 场景输入，需真实 LLM 派发 + 人工判分（期望行为是"拒绝直接写正文"等 LLM 行为断言），无任何 pytest/脚本包装、无断言器、无 CI 挂载。

**根因**: 压力测试被设计为一次性 T1 生成式评估 prompt，从未建立"prompt → dispatch → 行为断言 → 评分"的自动化回路（G0.9 的 scenario fixture 机制也未覆盖它们）。
**验证**: 实跑以上三条命令（输出见证据）；norecursedirs 证实 pytest 永远不会收集该目录。
**影响面**: 6 类反 rationalization 压力场景（偷懒结算/跳过 snapshot/audit-skipping 等）完全依赖人工触发，回归保护为零。
**建议方向**: 要么纳入 tiers scenario 体系（fixture + 期望行为断言 + G3.4 独立子代理评分），要么明确标注"仅人工 T1 材料"并在文档中删除"压力测试已建"的暗示。

### T1105 | 两小模块突变得分 35.1% / 32.4%（<50%），escalation 54% 突变体无测试触达 | 测试弱点 | P2

mutmut results | grep -c survived → 124    # 幸存者全部来自 x_gate_G_RECONCILE__mutant_*

# 第 2 轮: only_mutate=["src/shenbi/skill_utils/escalation/check.py"]，

mutmut run → 219/219  🎉 71  🫥 119  🙁 29  # 总分 71/219 = 32.4%；

                                            # （加消费方测试前后数字不变）
# check.py 仅 4 个顶层符号：EscalationSignal/detect_score_decline/check_escalation/main
# 专属 10 用例只覆盖 check_escalation；覆盖内杀伤率 71/(71+29) = 71%

**根因**: 测试只断言快乐路径的主干断言，不做边界值/负例强化（如 `range(1, 6)`、`MAX_RETRIES` 比较边界、字符串前缀匹配等比较算子突变大量存活）；`detect_score_decline`/`main` 完全无专属单测。

**建议方向**: 对存活突变 Top 类型（比较算子、常量、range 边界）补负例断言；为 `detect_score_decline`/`main` 补专属单测；基线建立后按 T1104 的 60% 目标迭代。

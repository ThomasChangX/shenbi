## 一、判定标准考古结论

### 1.1 文字契约：两句话，零操作性定义

G0.9 的全部契约文本只有两处：

- `AGENTS.md:97`: "Fixtures under `tests/fixtures/` are exclusively real skill outputs or upstream-generated copies (G0.9 prohibits hand-crafted mocks). All test scenario inputs must reference `tests/fixtures/` paths."
- `command-to-give.md:11`: "Skill 输入只能是 fixture。所有路径以 `tests/fixtures/` 开头。G0.9 检查。违反 → G0 阻断。"

"real skill output / upstream-generated copy" 在 `src/`、`docs/framework/`、tests 中**没有任何可操作定义**（何为"真实"、由谁判定、凭何证据）。全库唯一接近操作性定义的文本在 `tests/fixtures/calibration/README.md:20-22`："Never invented or hand-crafted for the test; always a genuine passage from a shipped chapter, imported canon, or fixture"——仅适用于校准锚点一族，且（见 T805）该定义自带循环漏洞。`src/` 中存在的 `provenance` 字段（scoring.py `_provenance`、dispatcher read-provenance）全部是评分/读取来源记录，与 fixture 溯源无关：**fixture 的 provenance 字段、schema、校验函数在框架代码中不存在**。

## 四、Findings

### T801 | G0.9 契约主体"fixture 真实性"零执法：门只验 scenario 路径前缀，不验存在性/内容/来源 | 契约执行机制 | P1

- **证据**: (a) 文字契约 AGENTS.md:97 与执法实现 `g0_purity.py:13-55` 的落差——实现只做反引号路径前缀检查（`:33` regex，`:35-38` 白名单 `tests/fixtures/`|`skills/`）；(b) scenario 引用空目录/不存在文件可过 G0.9（如 #10 `drafts/chapter-5.md`、#6 `truth/character_profiles/` 空目录）；(c) 全 `src/shenbi/` 无任何 fixture provenance 字段或校验函数（grep `provenance|真实输出|real output|upstream` 仅命中 scoring/dispatcher 的无关机制）；(d) "exclusively real skill outputs or upstream-generated copies" 在 repo 中无判定标准文本。
- **根因**: G0.9 把"输入纯度"（路径治理）实现为"来源真实性"（内容治理）的全部——契约的可执行子集被当成了契约整体。
- **验证**: `sed -n '13,55p' src/shenbi/gates/g0_purity.py`；`grep -rn "provenance" src/shenbi/ | grep -iv "scoring\|read_prov\|truth_embed\|capability"` → 空。
- **影响面**: 所有 T1/T2 场景的输入合法性声称；§二统计中 44 个被引用 C 类文件全部在此缺口下被消费。
- **建议方向**: 二选一并写明：(1) 给 G0.9 增加最小执法——scenario 引用存在性检查 + fixture 头部 provenance frontmatter（`origin: skill-output|upstream-copy|synthetic-sample` + 源路径）schema 校验，synthetic 显式降级豁免；(2) 收缩 AGENTS.md:97 的声称至实际执法面。禁止维持"声称 exclusively、执法零检查"的现状。

### T802 | 4 个 fixture 内嵌 "G0.9 note" 自我豁免 + frontmatter 虚构 `generated_by` 声称（且 YAML 非法） | 来源真实性 | P1

- **证据**: (a) arc-example.md / book-spine-example.md / book-strata-example.md / volume-summary-example.md 头部均有 `<!-- G0.9 note: This fixture is a format reference for scoring skill inputs, not a hand-crafted mock of skill output. Real outputs will replace it during round test execution on outline-example.md. -->`；(b) 同一 frontmatter 内 `generated_by: shenbi-memory-distill` / `generated_at: 2026-06-28`，但 git `c14f7e3`（ThomasChangX，2026-06-29，"test: add hierarchical memory fixtures (spec §9.7)"）一次性手工新建 4 文件共 104 行——"真实输出替换占位"的承诺从未发生，`generated_by` 是**关于来源的虚假元数据**；(c) HTML 注释嵌入 YAML 块使 `yaml.safe_load` 全部 4 文件 frontmatter 解析失败（"while scanning a simple key"）——任何严格 frontmatter 消费者都会出错，也证明无任何代码解析过它们（否则早已报错）；(d) 唯一消费者 = `scripts/lint_contract_fields.py` EXAMPLE_FIXTURES（:52-80，作 truth/book_spine|book_strata|volume_summaries|arcs 的字段基准样本）。
- **根因**: 作者明知 G0.9 声称与文件性质不符，选择在文件内写豁免注记而非更新契约或产出真实样本；顺手填了从未发生的 `generated_by`。
- **验证**: `head -8 tests/fixtures/arc-example.md`；`git show c14f7e3 --stat`；`python3 -c "import yaml,re; yaml.safe_load(re.match(r'^---\n(.*?)\n---', open('tests/fixtures/arc-example.md').read(), re.S).group(1))"` → SyntaxError。
- **影响面**: lint_contract_fields 的字段完备性检查建立在自述非真实的样本上（lint 绿 ≠ 真实产物满足 schema）；G0.9 声称在文件级被明知违反的先例——豁免以注释形式存在，任何机器检查都看不见。
- **建议方向**: 删除虚构 `generated_by/generated_at`；由真实 novel-output 弧段产物（xinghuo-ranqiong 已有 memory-distill 真实输出可镜像）替换或标注 `origin: synthetic-sample`；YAML 注释移出 frontmatter 块。

### T803 | G0.11 覆盖 4/91 且双侧缺失静默跳过（vacuous PASS），outline-example.md 的"源"本身无 pedigree | 执法覆盖面 | P2

- **证据**: (a) `MIRROR_MAP`（g0.py:13-22）仅 4 条；(b) gate 循环 `g0.py:492-495`：`if not fixture_path.exists(): continue` / `if not source_path.exists(): continue`——源或副本被删除时该条目从检查中消失且 G0.11 照常 PASS；pre-commit 版（check_fixture_mirror.py:29）同样跳过缺失源；(c) `tests/fixtures/outline-example.md` 的登记源是**根目录 outline-example.md**（同为示例文件，git 34c3d75 "add test fixtures from outline-example" 引入，无技能产物来源）——镜像校验在此退化为"example 与自身副本同步"，不提供任何真实性；(d) Z7-d F780 已指出 4 对 truth-*↔chapter-025 内部副本未登记 MIRROR_MAP（本轮印证并补充覆盖面视角）。
- **根因**: MIRROR_MAP 设计为"防 stale"（源更新后副本漂移）而非"验真"；静默 continue 把"登记项失效"降级为"无此检查"。
- **验证**: `sed -n '486,516p' src/shenbi/gates/g0.py`；`uv run python tools/check_fixture_mirror.py; echo $?` → 0（绿）。
- **影响面**: 3/91（volume-map + 2 snapshot，源=xinghuo-ranqiong 真实管线产物）是全部 fixture 中唯一有真实源哈希锚定的文件；此机制稍加扩展（登记所有镜像对 + 缺失即 FAIL）即可成为 G0.9 的执法载体，当前未利用。
- **建议方向**: MIRROR_MAP 缺失任一侧 → FAIL（而非 continue）；把 novel-output 真实产物→fixture 的镜像对全部登记；outline-example.md 的源改为真实技能产物或显式移出 MAP。

### T805 | calibration README 的"真实性"定义不可执法：schema 无 source 字段，且允许 "fixture" 作为 genuine 来源（循环定义） | 契约执行机制 | P2

## 六、总结

G0.9 的执法体系现状一句话：**契约文本声称"全部为真实输出或上游副本"，而全部执法（G0.9 前缀纯度 + G0.11 四条哈希镜像 + G0.14 内容锁）没有一处验证"真实"二字——91 个 fixture 中 4 个有机制性来源（4.4%）、17 个仅有不可验证的自述、70 个（76.9%）无任何来源主张，其中 26 个正被 T1/T2 以最高 78 处引用的频度当作真实产物消费**。判定标准不存在、校验机制验同步不验真、豁免以文件内自由文本注记存在（T802）——这是"声称 exclusively、执法零检查"的系统性缺口，其修复优先于任何单批 fixture 的更换（T809 传导链）。

    C17 · 测试基础设施配置失效修复（test-infra）

    背景（根因 + 证据）

    根因：承诺的质量防线（nightly、doc-links、benchmark、mutation、hypothesis 回归重放、golden 集）全部处于"配置齐全但不执行/执行即空转"状态——基础设施只有声明没有运行，失效无人发现（phase4 §1 候选元根因 F 的第四拆分）。

    代表证据： - F001（P2）：nightly.yml:8-16 schedule 被注释整体 DISABLED → doc-links 371 项测试零自动执行环境（本地工具未装即 skip + nightly 禁用，双层门禁挡死） - F1159（P1）：hypothesis「Examples ARE committed」回归重放双重死亡——.gitignore 压制使 43+ 失败样本从未入库（CI/新克隆零重放），叠加上轮 F1318（M）未修；T1107 协调者抽核：examples/ 44 文件仅 .gitkeep 被跟踪 - T1104（P2，实测复现）：mutmut 基线两个月未建立，且 3.6.0 下单文件 source_paths 复制出残缺 mutants/ 树必然空转——根因：venv editable .pth 令沙盒测试静默测回原仓库 - F741（P2）：tests/golden/README.md 承诺的 golden 评测集（chapter-N-original.md 等）不存在，无任何测试消费（T1106：README 承诺 10-20 章实际 0 文件） - F742/T1102（P2）：norecursedirs 写 tests/benchmarks（复数）但实际目录 tests/benchmark（单数）；benchmark 套件本身零用例 - F782/T1103（P2）：gate-outputs 7 份基线无自动化消费者且 4/7 已实质漂移，G6/G7 不可再生成（tests/rounds 不存在） - F783（P2）：mutation-score.txt 为 "BASELINE NOT YET ESTABLISHED" 占位，just mutate-check 恒失败；F1010：compare_mutation_score.py docstring 称 CI 使用实际未接线 - F1158（P2）：43 个失败样本全 stale——10 个测试 key 与当前 58 个 @given 函数 digest 0/10 匹配，本地重放价值为零 - F1160（P2）：.benchmarks 基准历史为单次冒烟 autosave，无真实基准套件、无跨运行可比性 - T1101（P2）：压力测试纯 prompt 无 harness——6 个 prompt md 零 CI/harness 引用 - T1105（P2）：两模块突变得分 35.1%/32.4% <50%，escalation 54% 突变体无测试触达 - T1109（P2）：G0.5 权重和校验永久 UNIMPLEMENTED，2026-06 基线曾以硬编码假 PASS 掩盖 - F732（P2）：doc-links 在任何场所都不执行且逐文件 spawn 子进程（性能面）

    目标

    每条防线二选一并落笔成文：激活（真实运行 + 结果被消费）或诚实下线（删除承诺与配置，文档不再声称）。消灭"配置存在但永不运行"的中间态。

    任务分解

    T1 · hypothesis 回归重放复活（P1 优先）

    1. .gitignore 放开 .hypothesis/examples/（保留内部缓存的忽略），提交现存 44 样本
    2. 清 stale（F1158）：对 10 个 digest 0/10 匹配的 key 重放定级——仍失败的修测试或删样本，全 stale 的整批重建
    3. CI 加一步 --hypothesis-show-statistics 或 replay 入口，使"样本入库"真正等于"CI 重放"（F1159 验收锚点）

    T2 · doc-links 防线落地（与 C23 共享）

    1. F001/F732：nightly 恢复 schedule 或拆分 internal-links 子集进 per-PR CI（推荐后者：内部链接检查无 npm 依赖可纯 Python 实现）；改造为批量解析而非逐文件 spawn
    2. 该防线上线即成为 C23 机械漂移修复的持续防线（C23 验收依赖此项）

    T3 · mutation 基线建立或下线

    1. T1104 修复路径：mutmut 升级/配置改为多 source_paths 支持的写法 + 排除 editable .pth 干扰（--paths-to-exclude/沙盒复制树方案二选一，实测裁决）
    2. F783/F1010：基线建立后 mutation-score.txt 写入真实值、compare_mutation_score.py 接入 CI（weekly）或删除；T1105 的低分模块登记为 C15 补测输入
    3. 若两周内无法修复 mutmut 空转：下线路径——删 mutmut 配置与 just mutate-check，justfile/README 同步（走 C24 语义一致性）
    4. F782/T1103：gate-outputs 基线消费者接线（G6/G7 回归测试读取）或删除基线目录与再生成声称

    T4 · golden/benchmark 诚实化

    1. F741/T1106：golden 集二选一——从 novel-output 真实树建 5 章最小集并接入差分断言，或删 README 承诺
    2. F742/T1102：norecursedirs 改 tests/benchmark；benchmark 建最小真实用例（chapter 解析吞吐类）或删套件；F1160 的 .benchmarks 冒烟数据清掉
    3. T1101：6 个压力 prompt md 要么接 harness（作为 T1 压力场景数据源）要么移入 docs/ 降级为设计材料

    T5 · G0.5 假 PASS 清理

    1. T1109：G0.5 权重和校验实现真逻辑（读权重表求和断言），删除硬编码 PASS 分支；基线记录更正

    批量清理（M 级成员）

    本簇无 M 级成员（18 条全 P1/P2）。

    验收标准（真实数据可复验）

    1. git ls-files .hypothesis/examples | wc -l > 0 且 CI 日志可见 replay 执行记录；对注入的 1 个已知失败样本 replay 会红（红灯验证）
    2. internal-links 检查在 per-PR CI 真实运行：临时把 README 一条链接改坏 → CI FAIL（记录后还原）
    3. mutation 路径定稿后：just mutate-check 要么以真实基线通过，要么该命令与配置从仓库消失（git grep mutmut 与声称一致）
    4. golden/benchmark：README/配置声称与磁盘一致（承诺集存在且有消费者，或承诺删除）——grep -rn "golden" tests/ README* 与实际对账
    5. G0.5：权重表注入一个和≠100 的负样本 → G0 FAIL（红灯验证）
    6. just check / just test 全绿；无新增 skip

    风险与回滚

    • 风险：激活防线后存量失败一次性涌出（doc-links 断链 ~371 项、mutation 低分）——先跑基线报告分级：阻断级立即修（多数与 C23 文档漂移同体），非阻断登记跟进
    • 风险：nightly/per-PR CI 时长增长——internal-links 拆子集 + 批量解析控制；mutation 限 weekly/按模块轮转
    • 回滚：每个 T 独立 PR；CI 工作流改动可整文件 revert；hypothesis 样本入库为纯新增无回滚风险

    Spec #81 · 观测完备性之网（observability-net）：让记录足以持续优化系统与 prompt

    日期：2026-10-28 ｜ 系列：regen-vol1 收尾（与 #80 invariant-net 配对：#80 管「生成对不对」，#81 管「凭什么知道、凭什么改进」） 状态：Done (PR #258 · 2026-10-29；P1 期交付——P2（lint_reads_reconcile/dispatch_replay/滚动归档）/P3（A/B harness/跨卷看板）遗留见 §6；运行侧验收=regen 续跑窗口)（历史修订 rev1 2026-10-29：设计审查轮 1 发现清偿——C1 归档模式改全量 blob/验收分期/逃逸舱检点钉死/API 面覆盖声明/L-A 例外条款；rev2：轮 2 五钉；rev3：轮 3 三重钉——求值点符号/loop_id 换源/快照捕获点；rev4：轮 4 三钉——§2 源矛盾清偿/落档锚点返回路径清单/并行波拓扑透传） ｜ 动机证据：docs/regen-vol1-observability-mining.md（Track A 手工首跑，五发现 O-1/O-2/O-3/A-1/B-1）

    触及的不变量维度：无（观测域——dispatch 归档/trace 加性字段/逃逸舱硬化，不直接触及 13 维普查任何维度；其归档产物供 #80 的 mutant 重放与 --as-of 审计回放消费）

    0. 背景与根因

    Track A 挖矿证明：元数据层（trace/账本/取证/裁决）已能产出结构层优化结论，但两类分析永远不可行—— 1. 因果归因：O-2（style_profile 35 次失配）用尽现有记录仍不可裁决，因为没有 dispatch 时刻的文件快照； 2. 对照实验：无 prompt/响应原文归档 → 任何 SKILL/prompt 改进只能等下一卷间接观察，无法回放验证。

    根因与 #80 同构：观测层也是反应式生长的——失败路径有取证（canary #16/#17 定点补），成功路径无归档；WARN 有发出（field_filter_missing_fields ×64）无消费。本 spec 把观测从「事故取证」升级为「常备完备」。

    两条铁律： - L-A 每个新增记录必须有具名消费者（anti write-only oracle——prop_registry 与 O-3 的同一教训，观测层不得复发）； - L-B 记录自身不得重演「累积无界」（settle 膨胀 ×2.8 的教训搬到日志层：内容寻址去重 + 配额熔断 + 滚动归档）。

    L-A 例外条款（recorder-first，仅限归档三件）：dispatch 归档本体与 feedback_ref/archive_path 两字段允许先记后用——O-2 的教训是 dispatch 时刻状态不落档即永久不可考，等消费者齐备再开记等于放弃这段历史；其具名消费者为 P2 dispatch_replay（含 #80 mutant 重放/金丝雀/--as-of 回放，见 §5）。为防 write-only 无告警退化，P1 即付最低消费者：observe_report 归档覆盖行（派发数 vs 归档数对账 + blob 存在性 + 去重率，§3 表首行）。

    1. dispatch 归档层（archive layer，= #80 所引 F21）

    每次 API 面派发（dispatch_helper._dispatch_via_api 成功/失败两分支各落一档；失败分支与现有 diagnostics/failed-write-* 并存——前者是结构化归档，后者是即视取证）落 observability/dispatches/{seq:05d}-{skill}-ch{N:03d}-a{attempt}.json；genesis 派发（chapter=None）记 ch000：

    {
  "seq": 122, "ts": "...", "skill": "shenbi-chapter-drafting", "chapter": 20, "attempt": 1,
  "model": "deepseek-v4-flash", "finish_reason": "stop",
  "skill_contract_sha256": "...",        // SKILL.md 的 git blob SHA——prompt 溯源锚（改版后可检漂移）
  "system_prompt_blob": "sha256:...",     // 完整 system prompt 进 blobs（同技能同卷高度去重）
  "user_prompt_blob": "sha256:...",       // 完整组装后 user prompt——任务指令+reads 全文+骨架注入+时间戳行，逐字节即模型所见
  "response_blob": "sha256:...",          // 响应正文
  "reads": [ {"path": "truth/current_state.md", "mode": "fields",
              "fields": ["系统演化阶段"],          // 契约声明（与 trace reads_manifest 同名键）
              "resolved_fields": ["系统演化阶段"], // 实际命中（archive 记录新增；manifest 不动）
              "matched_all": false,
              "blob": "sha256:..."} ],    // = 派发时刻磁盘原文快照（O-2 裁决口径）；过滤视图可由 fields 确定性重导
  "usage": {"prompt_tokens": 29213, "completion_tokens": 8102},
  "loop_id": 3, "feedback_ref": "sha256:..."   // §2
}
    • blob 策略（字节级复现的唯一路径）：user_prompt/response/system_prompt 三者与逐 read 原文全部进内容寻址库 observability/blobs/<sha256>，哈希即指针。不从 reads 重组 prompt——组装嵌入任务指令、wrap_untrusted_source 横幅、## Plan Skeleton 注入（volume_map 派生）、#77/#78 强制节拍注入、逐派发 Current time (UTC) 行（dispatch_helper.py:1391-1398），皆不在 reads blob 内，重组不可行。去重估测：reads 重复注入率极高（genre-config ×130/卷），~40-60MB/卷原始文本 → blobs 实存 ~15-25MB。
    • plan 约束（接线摩擦，价值门驳斥轮实证；rev3 加固捕获点，rev4 行号校准）：逐 read 磁盘原文快照需在 _build_skill_prompt 内于 filter_to_fields（:1100）与 _strip_meta_for_non_drafting（:1119）之前捕获（现有 raw_inputs[key] = content :1120 存的是过滤+META 剥离后视图——直接接线会把过滤视图当原文归档，静默毁掉 O-2 裁决语义）；共享上下文缓存命中的 read 归档缓存值非新读盘值（如实记档）。prompt 级 blob 无此依赖（组装产物在 _dispatch_via_api 作用域内）。
    • 覆盖面声明：本层只盖 API 面——regen 实跑全走 API 面（挖矿 223 DISPATCH 全部出自 API）；IDE 面 _dispatch_via_ide 无 DISPATCH trace 且弃 reads_manifest（dispatch_helper.py:3820 throwaway 注释自认），记为已知覆盖洞，不静默。
    • seq 指派（原子性，rev2 钉）：seq = 派发时在 .lockfile flock 下读档目录 max+1 取号——并行审计波（SharedAuditContext 共享派发）两路并发 max+1 会撞档名；跨 run 重启续号（按现存档推进，不归零）；档名撞即 archive_seq_collision WARN 跳过（容忍空洞，不重排——归档序号是历史标识，同 INDEX 编号纪律）。P2 index.jsonl 追加同锁。
    • 落档锚点（rev4 钉——返回路径清单，非 trace 调用点）：_dispatch_via_api 有六类不发 DISPATCH trace 的失败返回拓扑（write-failure 家族 :3720-3747、length-at-ceiling :3637、persistent-length :3682、post-cap-raise content_filter :3691、resend 失败 :3597/:3669）——归档插桩锚在返回路径清单（成功返回 + 全部有计费响应的失败返回，含上述六类；有 prompt 无响应的超时族照 §失败分支档形），不在 _emit_dispatch_trace 调用点——否则最有价值的失败归档（有响应正文的账单级失败）被静默跳过。
    • 失败分支档形（rev2 钉）：API 超时/空正文等有 prompt 无响应分支照落档（response_blob: null、finish_reason 超时分支实为 null 一并豁免）；prompt 组装前失败（连 reads_manifest 都无）不落档——archive_write_failed WARN 仅记「应档未档」的派发面。档内非空字段：除 response_blob、feedback_ref（首派无反馈可引）、失败分支的 usage 与 finish_reason 外全非空。
    • 默认开启（用户令「确保之后可以通过记录进一步优化」）；SHENBI_ARCHIVE_DISPATCH=0 可关（极端环境）——只关归档层，不关逃逸舱计数器（计数器独立常开：零 blob 开销，是 O-3 的修复本体）。写档 fail-safe：归档失败不阻断派发（与 _persist_failed_write_output 同纪律），但记 archive_write_failed WARN 并计入 §3 消费报表。
    • 配额熔断：observability/ 目录 > SHENBI_ARCHIVE_QUOTA_BYTES（默认 1GB，可配——测试可设 KB 级，§7 条 5 的离线形态）→ WARN + 跳过 blobs 新写（档与哈希照写）。如实记档：被跳过的 response 该次正文永久丢失；reads blob 仅当磁盘文件未变时可再导——而归档存在的意义正是证明「文件变没变」不可考——熔断即降级为「可验证（哈希在）不可复现（正文失）」。配额检查不逐派发全目录 walk：维护运行字节账 + 每 N 派发抽样校准。

    2. trace 结构化补全（加性字段，schema_version 保持 1）

    • DISPATCH 增字段（全部可选，旧事件兼容；versioning.py 的 assert_monotonic 只校验 schema_version 整数单调与未知高版本，payload 加键对其不可见；_emit_dispatch_trace docstring 明文「payload is a free dict, so no schema_version bump and no G7 chain impact」——结构性变更才升 v2 走 MIGRATIONS）：
    • loop_id：同 (skill, chapter) 的轮次序号——源 = state.chapter_loop.retry_budget_consumed（state.py:199；逐键单调、crash 持久、G4 硬败与监控回卷两路皆充，:3935-3940 注释明示「NOT retry_counts」），派发时快照。不用 retry_counts：它是连击非序数（成功即复位 :1690-1694、soft-continue 弹出 :4158），且监控触发的场景算术回卷（B-1 的本体案例，drafting 10 轮）只充 budget 不动它——接它会报 loop depth 0，复造本要修的盲区。token 账本 attempt 只见 API 级重试（6 次/卷），循环层重派至今不可见（B-1）。DISPATCH 事件仅 API 面发出（§1 覆盖洞同承）；RETRY 事件由 chapter_loop 发、面无关；
    • feedback_ref：重派反馈的 blob 哈希——循环反馈目前只活在代码里，「兜底反馈零信息」类问题（probe8 教训）从此有据可查（recorder-first，消费者 P2，见 §0 例外条款）；
    • archive_path：指向 §1 档案（同上）。
    • 新事件 RETRY：门检/监控触发的循环重派时记结构化原因（如场景算术差值 {scene: 2, actual: 1995, band: [1800,2000]}），替代只能翻 runner 日志的现状。action 为自由字符串（无枚举约束），G7 只验签名链+单调，新 action 直通。
    • plan 约束（状态线程，rev2 钉，rev4 补并行波拓扑——与 §1 raw_inputs 约束同级的接线摩擦）：_dispatch_via_api 特意不收 PipelineState（docstring :3414-3416「no PipelineState required — 8/13 call sites dispatch without one」），而 loop_id 源在 state.chapter_loop.retry_budget_consumed、feedback_ref 的反馈文本在 chapter_loop 拼入 prompt（:1090-1095）——派发函数内两者均不可得。落法（plan 定）：dispatch_skill（:4066，已收 state 形参但 API 路 :4121-4129 丢弃——恢复透传给 _dispatch_via_api）或 chapter_loop 计算后经签名下传，或派发函数外由调用方补发独立事件。并行波拓扑（rev4）：评审波经 parallel_dispatch.py:120-126 派发不传 state（波预算事后 _charge_wave_retries 结算）——review-group 是最大失败族（30/38 取证），波 DISPATCH 缺 loop_id 会在最大族复造盲区；波 runner（chapter_loop 侧）持有 state，须同批接线透传，不声明豁洞。genesis 键语义：genesis 重派键挂 ch1（_retry_key(chapter if chapter is not None else 1)，:1519）——genesis loop_id 快照即读 ch1 键计数，语义如实（创世章族共一个键位）。

    3. 消费者契约（L-A 的机制化）

    记录 具名消费者 层级
    dispatches 归档 P1 最低消费者：observe_report 归档覆盖行（token-ledger 派发行数 vs 归档档数对账——ledger 覆盖全部 post-prompt 路径；trace DISPATCH 数不作分母，六类失败返回无 trace 事件，§1 落档锚点；行粒度：ledger 每 attempt 一行，分母取每派发恰一行的 attempt=1 行）、blob 存在性抽检、去重率；P2 起 dispatch_replay 骨架（喂 #80 mutant/金丝雀） P1（覆盖行）→P2（replay）
    trace loop_id tools/observe_report.py（P1）：膨胀曲线 / loop depth / 失败簇 / 逃逸舱四表一键产出 P1
    trace RETRY 事件 observe_report 失败簇表：结构化原因聚类（替代翻 runner 日志） P1
    trace feedback_ref/archive_path dispatch_replay（P2）——recorder-first 例外见 §0 P2
    逃逸舱 WARN fail-fast 硬化（检点钉死见下） P1
    契约 fields 声明 tools/lint_reads_reconcile.py：所有 SKILL reads 的 fields: ↔ 项目内实际文件标题对账（lint_decisions_sources 三源对账同模式；O-1 类漂移在 CI 即红） P2
    归档写失败/配额跳过/序号撞档 WARN observe_report 末行汇总（archive_write_failed + archive_quota_skip + archive_seq_collision 三键分计） P1

    逃逸舱 fail-fast 检点（钉死四元组）： - 检点 id：escape_hatch_drift，HARD 语义——FAIL 时停循环、走既有 escalation checkpoint 暂停人工（漂移非重派可愈，禁止烧 retry 预算——具体化为传 budget_pre_consumed=True 且不预充：代码契约 :1583-1585 是「调用方已充过」，既有先例（G4 硬败 :4133-4144）是先充再传 True——本检点不照抄先例，零充直传；漂移是确定性已定因状态，非派发失败）。产物 = trace GATE_FAIL 事件 + write-audit.jsonl（record_audit_outcome 形态）；不写 gate-markers/*.json（G6 文件名错配事故教训，AGENTS.md 提交例在案）。 - 求值点（rev2 钉，rev3 符号重钉，rev4 行号校准）：派发后循环相位检查（chapter_loop 步进间隙读 observability/escape-hatch-state.json，非 G4——逃逸舱漂移是派发输入态不是输出结构态，挂 G4 会在浪费一次派发后才红）。GATE_FAIL 落 trace 走 audit/record.py 既有 record_audit_outcome（:22，action="GATE_FAIL" 形态）；HARD 路由直达 set_checkpoint(CheckpointType.ESCALATION)（:1677-1687）——不走 _handle_failure→_escalate_step_failure 全链（该链先派 escalation-review 付费 LLM 再 checkpoint；对确定性已定因的契约漂移是纯成本），也不走 check_escalation（soft-fail 信号评估器，消费点 :2033-2036）。不注册 G4_CHECK_MAP。读侧同取 .lockfile flock（或容忍半写 JSON 解析失败即跳过本轮）。 - 计数键：(path, fields)——O-1 实际漂移单元。不用 (project, path)：多技能读同文件不同 fields 声明时（planning 失配 vs drafting 匹配交错读 style_profile），交错复位互掩真漂移、或异技能偶发失配凑满 3 次假 FAIL。 - 复位规则：同键 matched_all=true 的读复位该键连击计数。 - 缺失语义：observability/escape-hatch-state.json 不存在 → PASS（既有项目/特性前历史不追溯失败——向后兼容硬约束）。 - fields.py 逃生舱（spec #9 R3 / F218）保留——契约错了不该断生成；但同键连发 3 次证明是漂移不是偶发，必须浮出为检点失败。计数器写侧在派发路径 reads_manifest 构建点（_build_skill_prompt 共享路径——API/IDE 两面都计数，与 §1 归档的 API 面覆盖洞解耦；legacy CLI subprocess 面（dispatch_skill :4156+ 子进程）不做字段级过滤——codex 子进程自读 workspace、注入仅 manifest 形态（executor.py:219-225）——逃生舱机制在该面不存在，计数器自然 N/A 非豁洞）；写走 truth_io .lockfile flock 纪律（并行审计波共享计数器，无 lost-update）。

    4. 保留与轮转（L-B）——P2 批

    • dispatches/ 按 --through <ch> 滚动压缩为 dispatches-001-060.tar.zst（对齐 just pool-archive/ledger-archive 的窗口纪律）；
    • blobs 引用计数：滚动归档后零引用 blob 回收；
    • observability/index.jsonl：每派发一行指针（seq/skill/chapter/sha），跨 run 聚合查询不触 tar。
    • P1 过渡：以上三者均 P2；P1 observe_report 直接扫 dispatches/*.json（单卷 ~500 档量级可承受）。

    5. 与 spec #80 的接线

    • 80 §1 查询面 --as-of N 的跨章审计回放、§5 金丝雀、§3 mutant 重放，全部消费本 spec §1 归档——#80 文档中 F21 即本节（#80 归档版 :85 声明在案；三消费方均在 #80 P2 路线图，近期具名消费者=本 spec §3 表）；

    • 80 facts store 的投影层省流（settle ×2.8 膨胀的根治）以本 spec observe_report 的膨胀曲线为验收度量；

    • 两 spec 共享伤口语料：tests/fixtures/invariant-mutants/ 供门检红测，observability/ 供 prompt 改进回放——职责不重叠。

    6. 分期

    • P1（本批起）：§1 归档 + blobs 去重 + DISPATCH 三加性字段 + RETRY 事件 + 逃逸舱 fail-fast + observe_report 骨架（四表 + 归档覆盖行；justfile 挂 just observe-report <dir>）+ O-1 一行修复（已随挖矿批次在项目侧完成——repo 不跟踪 novel 目录，此处仅存目）。
    • P1 验收（离线形态，SDD 代码交付边界内——F947 纪律，fixtures/tmp_path 驱动，禁真实 dispatch）：归档写档 + blob 去重 + user_prompt_blob 解引用字节级复现；fail-fast 3 次触发与四元组语义（复位/缺失 PASS/键隔离）。
    • 运行侧验收（运行验证阶段动作，不在 SDD 边界内——#80 先例）：regen 续跑 2 束（vol1 续章）后 observability/ 可字节级复现任一 drafting 派发的 prompt 与 reads。口径统一（rev2）：P1 期运行验证=vol1 续跑窗口；§7 的「下一卷 5 章」窗口是 spec 全期（P2 后）完成口径，两者并存不混。

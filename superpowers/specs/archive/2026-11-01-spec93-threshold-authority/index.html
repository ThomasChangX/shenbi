    0. 根因

    对账器结构上抓不住它存在的目的：lint_threshold_reconciliation 自认「parsing checker constants is out of scope」（:5-8 与 :36-38）且「always exits 0 (WARN-only)」（:81/:99）——比较 SKILL.md ↔ allowlist JSON，而 allowlist 的 bounds 是第三份手拷（4 条 entry × [15,40]）；真执法器只验文件存在（:44-48）。改 checker 为 [18,45]：无红无 WARN——进了 just lint（justfile:53，经 just check :22-24）却无条件放行。判定式 d_hi < lo or d_lo > hi（:67）是相交而非包含——SKILL 写 10-20 与硬带 [15,40] 相交即放行，带内漂移结构性漏检。

    r2 事实校正（r3 维持）：执法器当前没有可读常量（内联字面量），故「lint import 读常量」需先提取（T1a）。SKILL「目标比值（按卷型）」四档（15-25/30-40/15-25/15-25，SKILL.md:174-177）落在硬失败带 [15,40] 内——allowlist 4 条 bounds 相同是设计而非漂移，本 spec 不指控其为复写错误，只去掉「bounds 作为第三源」。

    散文↔门值分歧（1/3000 vs 1/1000）：门侧注释自认「relaxed for automated gen」（:931），散文侧 5 处仍教 1/3000 为铁律。若为「提示比门严」的故意设计则完全合理（prompt 工程），问题仅是决策未成文。修法=r2 改入文档，不改 SKILL.md 散文（SKILL.md 指令改动会改变 LLM 行为——束4 验收后窗口 prompt 行为红线维持）。

    r3 新增根因 · 疲劳词门-契约键形断裂：门的意图是读 genre-config 的疲劳词表（_check_fatigue docstring 自认「genre-config 阈」，:967），但 gc.get("fatigue_words", FATIGUE_BASE)（:970）读的是 snake_case 顶层列表形状，而 genre-config 技能契约定义的是 camelCase 嵌套对象 fatigueWords:{禁用:[],慎用:[],替换建议:{}}（genre_config.py:50 alias + SKILL.md:91-93 模板 + fixture 实证）——read_genre_config 返回原始 json 不经模型归一化（shared.py:741-744），真实技能产物下该键永不存在，门恒用内置 FATIGUE_BASE 计数。这不是裕度而是断线：r2.2 拟成文的「疲劳词 ≤3（原）vs ≤8（门）」对照在现状下无数据流支撑——两侧数的是不同的词表（慎用报警线 vs 内置基表）。

    1. 任务分解

    T1 · 对账器读执法器（含前置常量提取）

    • T1a：contracts/skills/pacing_design.py 提取 CONSTELLATION_HARD_BAND: tuple[int,int] = (15, 40)（命名对齐 gates/shared.py band 元组先例 :64-65），validator 改用它（行为零变化，红测：现值通过/越界失败照旧）。落点裁决已预答（预答栏 ⑤）：不落 config/thresholds.py；
    • T1b：lint_threshold_reconciliation 改 import 该模块读常量（tools 可 import src——check_severity_vocab.py:18 / facts_backfill.py:27-30 先例；lint_private_imports 只扫 tests/ 不拦 tools）；删 allowlist 的 bounds 字段（deletion test：删之严格增收信息保真）；判定式从相交改包含 d_lo >= lo and d_hi <= hi（否则只是把第三源换成第二源，结构性漏检照旧）；r3 硬化：keyword 升必填——缺 keyword 的 entry 在 strict 下 FAIL、非 strict 下 WARN（博弈路径 ②实测：缺 keyword 时 scope=整行，RANGE_RE 抓第一个 range，行首 range 恰在带内则静默校验错列）；
    • T1c：新写 --strict 模式（对照 lint_key_reconciliation --strict 先例 justfile:44；justfile:33 已有本 spec 预留钩注释）并接线进 just lint；strict 的 FAIL 面=五面全保留：file_missing / checker_missing / keyword_missing（r3 新增）/ no_range_found / drift-vs-constant（越出常量带）。测试重写义务（r3）：tests/unit/tools/test_lint_threshold_reconciliation.py 现锁 WARN-only exit 0 + bounds 形状（:23-:72）——同批重写为 strict 语义 + 无 bounds schema；越界场景构造：entry file 字段以绝对路径指向 tmp SKILL 副本（lint 的 REPO_ROOT / entry["file"] 对绝对路径 rhs 保持原值）；
    • 误报处置声明（维度 5）：现役 4/4 entry 全带 keyword、四档 CONSTELLATION 值包容式判带内全过（亲验零存量红）、WARN-only 周期已多轮零 WARN（test_lint_clean_on_repo_allowlist 锁存）——直接 FAIL 不设 shadow；

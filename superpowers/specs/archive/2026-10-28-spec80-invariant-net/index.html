    Spec #80 · 不变量之网：规范事实库、四槽门检、变异测试覆盖（invariant-net）

    来源：regen-vol1 运行（ch1-24）G3.4 评分 83.5 CONDITIONAL 暴露的五类跨章缺陷根因分析 （裁决 #031 + rubric-score-24.md 五维伤口；系统性调试会话）。根因三层：L1 模型行为偏离；L2 五个「write-only oracle」 维度（有台账无门检）；L3 门体系反应式生长、从未做不变量普查。 方法：declare-then-verify（钩系统 24 章零漂移的配方）推广到全部维度 + 变异测试闭环。 优先级：🔴 P0（内容修复的 gate 保障依赖 P1）。 Status: Done (PR #256 · 2026-10-29；P1 期交付——P2 前置三项见 §6；rev1 驳斥七项；rev2-4 R1-R3 审查修正 30 项；rev5 R4 修正：facts_ops schema enforcement 触点/identity 对账比较面+重生成=陈旧行重写/severity=HARD/空种子语义/mutant 义务域限定/F16s 纯读者/--chapter 相关性语义——2026-10-28）

    触及的不变量维度（T10 自补——普查表 docs/framework/invariants.md）：恒等 identity／持有与经手 props／枚举计数 counters（P1 到期三行，facts 承载+mutant 义务）＋ 能力活性（P2 F18 core_motif_touch）。P3 迁移面（promises/情绪等）见 §6。

    0. 背景与根因（浓缩）

    缺陷 L1 直接原因 L2 系统缺口

    1. 规范事实库与唯一查询面（facts store）

    1.1 结构

    • truth/facts/<dimension>.json——按维度分文件（identity / props / counters / knowledge / promises(钩) / emotion），schema 校验（pydantic 或 jsonschema）。
    • 增量 op 协议：settle 只发结构化事件（{op: prop.transfer, prop: 骨哨(旧线), from: 帖木哥, to: 那罕, evidence: "chapter-20.md L218"}），facts store 应用 op 并校验状态机合法性（无来源的二次获得=拒收）。这同时根治 matrix/整档 content_dropped 族（模型不再重写整档）。拒收语义（rev2 I2）：op 校验失败 → typed exception（exceptions.py 家族）+ settle 门 FAIL，走既有 attempts/escalation 协议；fail-fast 在 Markdown upsert 之前（双写下 Markdown 行不落盘，无半写态）。写路径分期（rev2 C1）：P1 起 settle 对三维双写（结构化 op 供 facts 应用 + 既有 Markdown 行 upsert 照旧），P3 才退役 Markdown 整档重写——不存在 facts 陈旧窗口。双写分叉语义（rev3 R2-I2，裁定方案 b）：Markdown 行仍由 settle 模型面照旧自写（契约零改动，向后兼容最大化）；G4.ss 增 op↔row 一致性断言（facts 为 canonical，声明面与事实面不一致即 FAIL）——双写目标逐维钉死（rev4 R3-M4）：props=registry 行（唯一真双写面）、identity=对账检查（facts↔name_registry，非双写）、counters=纯 facts 新面（无 Markdown 孪生），故 G4.ss 断言范围=props + identity 对账；op→row 机械渲染=P3 投影层实现形态（届时分叉面消失）。gate 纯度边界（rev2 I3）：op 应用是有状态写侧，住 facts 模块；门检是纯读者（AGENTS.md 幂等律）。op 传输通道（rev4 R3-M7）：op 走 state-settling decisions sidecar 的加性键 facts_ops（decisions-v1 schema 加性扩展不 bump 版本）；P2.5 rationale 交互=routine op 免 rationale、拒收/manual_override 必带；lint_decisions_sources 三源同批登记。
    • 投影层：现有 truth/*.md 变成从 facts 渲染的投影（渲染器 src/shenbi/facts/projection.py——rev2 I8 订正：框架侧模块，非项目数据目录；Markdown 面向人/LLM 的可读性不变，投影头部带 > projected from facts/<dim>.json — do not edit）。迁移分两期（见 §6），存量 Markdown 表在迁移前保持现状不阻塞。
    • 查询面：shenbi-facts query --dim props --chapter 20 [--as-of N]——返回该维事实（含 as-of 历史态，供跨章审计回放；--as-of 消费方=P2（canary/F19 审计回放），P1 查询面=现态紧凑视图——rev4 R3-M6；--chapter P1 语义=相关性范围（本章相关实体子集），非历史点——rev5 R4-M5；op log 即 P1 真实产物，P2 落地平凡）。planning 投影（rev2 I4）：planning 上下文装配消费现态紧凑视图（当前 owner + 本章相关实体，extractor 哲学复用），token 面有界；完备历史/--as-of 仅供审计/金丝雀。消费方：chapter-planning 上下文装配（替代猜）、G4 门检 oracle、审计契约 reads、金丝雀审计。

    1.2 首批入库维度（P1）

    props（owner+事件链+状态机）、counters（鉴录名数等单调计数）、identity（人物别名→叙事名映射+当前叙事名）。promises(钩) 迁移=P3 期（rev3 R2-I1 对齐 §6——钩系统四槽已齐备零漂移，迁移优先级最低；pending_hooks 证据行届时保留 Markdown 投影，规范态进 facts）。

    1.3 种子真值源（rev2 I6）

    facts 种子从修复后章节正典（fixed chapters as canonical）派生；truth registry prose 单元格不作为种子源——已核实 registry 陈旧（name_registry 赵三行与 prop_registry《鉴录》行仍记 pre-fix「第三个名字」，与修复后 chapter-9.md:151「第一页三个名字」矛盾）。registry 在 backfill 后重生成——重生成=陈旧行重写（rev5 R4-I2：赵三行/《鉴录》行/「临」备注行等已核实陈旧的行），绝不整文件重生成（72 行 settle 撰写的 prose 备注是确定性工具不可再派生的内容，保护）。identity 对账比较面（rev5 R4-I2）：别名/旌名行 ↔ facts 别名集；登记名行的 prose 备注（「全卷一致」等与 narration_name 相悖的注记）显式出范围——对账不得永久红。

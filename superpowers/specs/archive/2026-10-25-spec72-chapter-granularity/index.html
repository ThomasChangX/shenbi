    Spec #72 · 平台章粒度改革（chapter-granularity）

    Date: 2026-10-25 | Status: Done (PR #248)) | Severity: 🟥 P0（地基） | 方法: 方案 C——平台章原生粒度 + 场景簇批量派发（一次派发 2 章）+ 声明式发布切分 | 系列: 市场适配层（novel-market-overhaul） | 依赖: 无 | 范围: genre-config 常量与平台参数（含契约闭键集四站）/ novel.json 章数口径 / chapter-planning 与 chapter-drafting 双章 bundle 契约 + chapter_loop 派发循环 / 确定性拆分器 / G4 逐章校验扩展 / 章节修订×场景标记一致性 / release_split v2 / volume-budget 重排接线

    源自 2026-10-25 总设计 2026-10-25-novel-market-overhaul-design.md §2。用户决策：双平台（起点粒度生成为主、番茄发布层适配）；方案 C（原生+批量派发）。总设计 §2.3「修订路径：批量产物先拆分再按章修订」由施工面 9 承载；本 spec 覆写总设计 §2.2 的 scenes.jsonl 边车条款——场景边界真源改为章文件内标记，sidecar 索引整体退役（R3-I1：无消费方的索引 = dead-wire；章内标记可随时确定性重导任何所需信息）。

    1. 定位与边界

    • 问题：chapter_word.default=7600 锚定了 1316 章的生成粒度，每万字节拍数 ≈1（头部 ≈3）；release_split 启发式切分不带爽点/钩子意识，切分点打乱节拍布局。
    • 本 spec 改生成与发布的粒度合同，不改内容规则（引擎/节奏归 #73/#74）。
    • 卷界按字数锚定不变（12 卷历史锚不动）；旧九章全弃，无迁移包袱，旧启发式直接退役。
    • 存量时序约束：本 spec 落地后、#79 删旧章前，不对 novel-xinghuo-vol1 现存 10 章（约 7600 字/章）执行 G2/G4/G6（新字数带下 G2/G4 必红；G6.1 最少章数阈值 ceil(3125×0.5)=1563 vs 存量 10 亦红）。pipeline-state 的 1316 章口径由 #74 重排 + volume-budget --apply 收敛；并存期间唯一预期红面 = volume-budget 的 re_budget_pending（设计内报告；G0.3 只报告 ceil 从不对比 novel.json，无其他消费方炸）。
    • 场景标记的耐久性合同：<!--SCENE--> 场景标记保留在终稿章文件内（独占一行 HTML 注释，渲染不可见）；===CH:n=== 章界标记只存在于 staging 簇产物。发布层生成更文本时剥离标记（两档皆剥）。场景边界唯一真源 = 章文件内标记；无 sidecar。标记行识别谓词单源（R5-M1，四消费方——拆分器/G4 场景数/修订 diff/v2 边界检测——共用一个定义）：line.strip() == "<!--SCENE-->"（全等，剥首尾空白，大小写敏感），实现导出自 scene_splitter 单点。

    9. chapter-planning 双章 bundle（skills/shenbi-chapter-planning/SKILL.md）：一次派发输出两份独立备忘（writes 增 plans/chapter-{N+1}-plan.md brace 形态 + 对应 decisions sidecar；卷末单章簇时同步退化为单备忘，见 3b-①）——各自章尾张力拍、场景字数预算两型规则（R3-I7 + R4-I3 + R5-I3 组合约束与预检）：场景分两型——独立型 [1800,2000]（单场景成更）、配对型 [900,1400]（相邻场景配对成更）；章组合约束（保证章带 [2800,4000] 与更带 [1800,2800] 双可满足）：2 场景章 = 两独立型（和 [3600,4000]）；3 场景章 = 三配对型（和 [2800,4200] 取带内，即和 ≥2800）或一独两配（和 [3600,4800] 取带内）；灰域 [1400,1800) 属规划脆弱域——planning 禁用，拆分器对单场景字数落灰域即熔断。跨章可打包性预检（R5-I3，planning G4 新检查，替代不可执行的「发布期回 planning」）：G4 对备忘声明的场景字数预算序列做确定性可打包性验证——输入 = 前章末场景字数（从已收束章文件 chapters/chapter-{N-1}.md 按 §1 单源谓词标记派生——声明预算 ≠ 实际，拆分器只验域不验等值，预检须用实际值）+ 本双章两序列，模拟 v2 贪心打包（首个 bundle 无前章，跨章预检跳过，仅验本 bundle 内自洽）；不可打包（如前章尾配对型 + 本章首独立型 ∈ (1900,2000] 组合越过 2800）→ G4.cp FAIL → 本 bundle planning 重派（时点在 planning，settled 章不动——预检可执行）；v2 残余不可打包 = 防御性 exit 1（理论不再触达，触达即规划违约漏网报人工）；每场景收束钩声明（钩原文一行）；共享一次上下文读取。
    10. chapter-drafting 场景簇契约（skills/shenbi-chapter-drafting/SKILL.md）：一次派发 = 连续 2 章（约 6400 字）；全部产物走 staging（bundle + 两份章级 decisions sidecar——uses_staging 既有约定，且 G4 文件解析对 staging 步有 staging/ 前缀语义，R3-M8）；bundle = staging/chapter-{N}-bundle.md，内含每章完整现行章结构：===CH:n=== 行起章、## PRE_WRITE_CHECK 块、双 H1（其二为章题）、正文（含 <!--SCENE--> 标记行）、## POST_WRITE_SELF_CHECK 块（解剖顺序=现行真实章：PRE 在 H1 前——strip_narrative_body 的 PRE 剥除边界是下一 #/## 行，H1 前置会把正文整体吞入剥除段；R3-I4：拆分章文件与现行单章产物完全同构，G4.pre/post、G2.8/2.9、release_split 双 H1 题机制零改动）；每场景末行 = 备忘声明的收束钩原文（逐字，谓词：声明文本剥空白后为场景末非空行子串）；每章末尾落在备忘声明的章尾钩上。 3b. chapter_loop 派发循环改造（src/shenbi/pipeline/chapter_loop.py）：CHAPTER_STEPS（:143-264）单章步进 → 双章 bundle 步进。约束：① bundle 不跨卷界——卷末奇数章 = 单章簇（step1 卷界 checkpoint 后重新对齐配对）；② step 完成度 bundle 原子（两章同进退）；③ ghost-chain 守卫要求两份拆分产物齐备；④ 新确定性步 pipeline-scene-split（步名钉死，R5-I2；pipeline- 前缀循 pipeline-volume-align/pipeline-post-draft-extract 确定性步惯例；drafting 步后）：拆分器消费 staging 簇 → 拆出 chapters/chapter-N.md(+N+1)（剥 CH 标记留 SCENE 标记）+ decisions sidecar 直通晋升 → 逐章 G4.cd 终验，manifest 闸记录按章分别落 N 与 N+1（只落 N = follower 章侧永缺拆分键永不可打包）；drafting 步 G4 面覆盖两份 staging decisions sidecar（N 与 N+1，_resolve_g4_files 单章参数化须扩）——bundle 非章形态不进 G4.cd；drafting 步 output_path 不设 md 路径，防 _resolve_g4_files 后缀路由把 bundle 误喂 G4.cd（R4-I8）；crash 恢复 = 从 staging 簇重放（拆分确定性幂等），staging 清扫机制不变（拆分步即时消费）；⑤ 审计按簇派发但报告工件保持逐章（chapter-{n}-review-summary.md 等下游 _get_audit_history/G3 形态零改动——簇 prompt 一次产出两章报告）；⑥ _wave_savepoint 按簇记账但两章 audit_results 皆落（缺 N+1 = 级联盲区）；⑦ post-draft 内联块重挂（R4-I2：现状 :3731-3744 的 _check_volume_map_alignment/_run_post_draft_extract/_run_g4_checks/_check_word_count_bounds 以 "chapter-drafting" in step.skill 触发且读 chapters/chapter-N.md——拆分步插入后该文件彼时不存在，四检查静默停摆）——整块改挂 pipeline-scene-split 步（章文件已存在的首个时机），两章各跑一遍。
    11. 确定性拆分器（src/shenbi/pipeline/scene_splitter.py 新增，由 3b-④ 新步调用——独立存在零调用 = dead-wire 禁止）：读 staging 簇，按 CH 标记拆章；校验每章字数带 2800-4000（读配置）、场景标记数 ≥2、每场景字数落两型域 [1800,2000]∪[900,1400]（灰域即熔断，施工面 2 组合约束的执法点）、CH/SCENE 标记完整（缺失=硬失败 exit 1 熔断重派，失败归类既有 FailureClass.DETERMINISTIC_GATE，不新增状态域）；剥离 CH 标记、保留 SCENE 标记；decisions sidecar 直通晋升。G2/G4 作用于拆分后章文件；staging 簇不进 G2 章检查（拆分器硬校验即其门）。计数口径：字数统计剥标记行——strip_narrative_body 与 G4.cd 自建段面（chapter_drafting.py:388-392）两处都须剥标记行（R3-M6）；G4.cd content_uniqueness 指纹（:354）哈希前同剥（R4-I10）。
    12. G4 逐章校验扩展（src/shenbi/gates/g4/chapter_drafting.py）：现状 chapter_end_hook（:435-484）已按文件逐章启发式；新增：每章场景数 ≥2（读章文件内 SCENE 标记）；收束钩「声明 vs 实际」匹配（plan 备忘钩声明 ↔ 章文件各场景末行，谓词见施工面 3）；标记行不参与既有检查计数（施工面 4 两站点）。
    13. release_split v2（tools/release_split.py）：起点档 1 章=1 更（重题直发——双 H1 题机制现状不动）；番茄档以场景为原子打包（允许跨章组更），硬规则四条——每更 1800-2800 字（读 chapter_word.fanqie_update）、更边界只落 SCENE 边界（读章文件标记）、每更必须以声明的场景收束钩收尾、禁切场景中部；打包算法 = 贪心组相邻场景命中 [1800,2800]；不可打包 = 防御性切分失败（exit 1，报 offending 场景字数清单——规划期预检（施工面 2）后理论不再触达，触达即规划违约漏网报人工）；更文本剥离标记（两档皆剥）。旧启发式退役（SCENE_TRANSITION_WORDS/TIERS 常量/段落窗口算法 plan_releases 族）。已收束窗口（R4-I4 + R5-M3 + R6-I1 钉死）：打包域 = 已收束章集合——数据源 pipeline-manifest.json gates.chapter_loop 相位逐章闸记录，已收束 := 该章每个 (skill,gate) 键的最近一条记录为 PASS 且 pipeline-scene-split 步 G4 键存在（latest-per-key 语义，get_gate_result gate_manifest.py:154-169 既有基建；PASS 严格匹配不含 WARN/SKIP）；必须键 = 每章的 pipeline-scene-split 键——drafting 步按 bundle 派发、其 G4 记录只落 leader N，follower 章 N+1 无 drafting 键属预期结构不排除（生成链证据即拆分键）；拆分键缺席 = 章未走完全链，空洞不纳入；--through <N> 显式覆盖语义 = 取 1..N 内仍满足已收束谓词的章（收窄不豁免，空洞同样跳过）。CLI 合同不破：位置参数 dir + --platform（缺省改读 genre-config.primary_platform，无键回退 v1 默认 fanqie）保留；--title-pattern/--renumber-published 保留。同批重写债披露：tests/unit/tools/test_release_split.py 38 用例随 v2 重写。冻结机制保留——当前零已发布更 = 零冲突退役窗口，v2 须在任何真实发布前落地。
    14. volume-budget 重排接线（src/shenbi/pipeline/volume_budget.py）：章数数学随 default=3200 自动生效（_implied_total :190-205）；word_floor 口径随地板统一改 min；--apply（:329-340）保持只写 novel.json total_chapters + 骨架同步。卷内章数按 3200 重排（卷一 45.6 万字 → 约 143 章）——重排执行归 #74。
    15. 审计批量：LLM 审计同维度按簇批量派发（×1.19 而非 ×2.4）——落点 chapter_loop.py:3010-3121 审计两波 prompt（:3060/:3094 → 簇形态）+ _wave_savepoint :3079/:3117 按簇记账（3b-⑥）；G2/G4 逐章执行（本地代码无 LLM 成本）。
    16. 章节修订 × 场景标记一致性（承载总设计 §2.3 修订路径）：批量产物先拆分再按章修订（shenbi-chapter-revision 仍 updates chapters/chapter-N.md merge_prose，修订粒度不变）。修订合同扩展：修订不得删除/挪动 SCENE 标记行与场景末钩行。修订后重验 = 新接线（R3-C1：现状修订步 G4 只验 *revision*.json，正文从不复验——chapter_revision.py:64-67 跳过一切非 revision JSON）：step15 后对修订章 (a) 标记行 diff vs chapters/chapter-N-pre-rev.md 既有备份（chapter_loop.py:2091-2111）——按 §1 单源谓词取标记行，数/次序变化即 FAIL；(b) 重跑 G4.cd 场景检查族（场景数 ≥2 + 钩声明-实际匹配）+ 字数带复检（R5-M2：merge_prose 可推章出带——total_chars_md_text 口径、剥标记行，同拆分器终验口径）于修订后正文。FAIL → 回修订重派。

    0. 根因与方案选择

    「哪些技能挂 G4 checker」smeared 在 4 个手工结构：G4_CHECKER_KEYS（generic.py，frozenset）/ G4_CHECKER_SKILLS（gates/shared.py）/ SHORT_MAP（gates/cli.py，dict）/ build_checkers()（generic.py，dict）——#89（2026-11-14）落地后实为 5 处涂布（+GENERIC_ONLY_ROSTER shared.py:814，问题被强化而非缓解）。加一个 checker = 编辑 5-6 处；lint_registry_reconcile 以 AST 解析框架自身源码对账（读码不 import 码）——对账存在不等于编辑面缩小。

    方案对比（r2 裁决；r2.3 修 C 的编辑面数字与载体）：

    方案 编辑面 新增机制 裁决
    A. frontmatter contract.g4_checker + sync_contracts 生成 1（SKILL.md） 生成器 + schema 位 + 30 个 checker 技能的 SKILL.md 回填 否决：把「哪个函数存在」这件代码级事实搬进散文文件；30 处一次性回填 + 契约 schema 变更（AGENTS.md 契约升级纪律的破坏面）
    B. 生成 Python/JSON 模块 1 构建步 + import 时读档 否决：本仓 codegen 先例（deps.json/index.json）都是数据面；checker 名册是代码面，多一层生成反而引入自举/幂等问题
    C. 一个权威集合 + 派生（采用） 3（新 checker 文件 + 权威集合一行 + build_checkers wiring 行；若该技能现居 GENERIC_ONLY_ROSTER 则 4——再删其 fallback 行） 零 ✓ 纯 Python 派生，无构建、无新文件格式。（r2.3 修正：原「2」漏计 build_checkers wiring——函数对象不可派生，不写 wiring 行则 set(checkers)==G4_CHECKER_KEYS assert 当场红；「其余手工编辑=0」限定为名册面——SHORT_MAP/G4_CHECKER_SKILLS 派生化后自动通过）

    先例约束：spec #9（spec 日期 2026-08-14；plan 2026-08-24）裁决「lint 对账优于 g4 消费 pydantic 契约模型」——本 spec 不动该裁决（不新增契约模型消费）；C 方案正是在既判框架内把「可机械推导的手工副本」删掉。

    1. 任务分解

    T1 · 权威集合收敛（G4_CHECKER_KEYS 为单源）

    • r2.3 载体改判（原 r2.2「gates/g4/roster.py 零依赖叶」被证伪）：gates/g4/__init__.py:7-14 eager re-export generic 六符号（gate_G4 族）——import shenbi.gates.g4.roster 必先执行包 init → generic → shared+structlog 全链，「零依赖叶」失真：①cli 顶层 import roster → 冷启动回退全链成本（正是本 task 要避免的）；②shared:776 处别名 import roster → shared（半初始化）→ g4 包 init → generic → from shenbi.gates.shared import chapter_no/fail/passed/...——六助手（:190/:199/:211/:224/:604/:651）今日恰都定义在 :776 之前才能活，顺序脆弱，且逆转 #89「shared 出鞘/no g4 import」性质；
    • 采用方案（r2.3 定判，不再是「plan 定」；r2.3b 钉死权威名）：gates/shared.py 为权威集合宿主——字面量挂 G4_CHECKER_KEYS 名下（r2.3b 定：lint _checker_keys/g5.py:341 的消费名——AST 提取器对 Call(Name) 别名形态返回空集，字面量必须在解点名下），G4_CHECKER_SKILLS = G4_CHECKER_KEYS 别名行（g0.py:110-122 module-level from shenbi.gates.shared import G4_CHECKER_SKILLS 零改动；与 GENERIC_ONLY_ROSTER 同文件成干净二分）；generic.py 改 from shenbi.gates.shared import G4_CHECKER_KEYS（generic 本就 import shared :14-20，零新边零新文件），G4_CHECKER_KEYS 注释「String-only so lint tooling (and g5) can import it without pulling the per-skill checker modules」继续成立（shared 比 generic 更轻）。generic.py 旧 frozenset 删除（防遮蔽副本）；
    • SHORT_MAP 派生移入 cli 的 G4 懒加载分支内（唯一消费点 cli.py:169 本就在该分支，分支内已付 generic 链 import 成本，边际为零）——cli 顶层零新 import，冷启动不回退；

    • 备选（plan 期若发现 shared 宿主有未知破裂面才启用）：gates/roster.py 顶层叶——gates/__init__.py 仅 docstring（6 行），#85 src/shenbi/truth_format.py「only acyclic landing point」同模式。

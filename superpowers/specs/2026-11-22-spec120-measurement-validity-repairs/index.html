    日期：2026-11-22｜ 系列：v8.1 测量语义 lens 首批清偿｜ 状态：Design（r1.1，2026-11-24 Revised）｜ 优先级：🟠 P1

    动机证据（2026-11-22 四臂盲测＋GLM 逐条亲验，底账 docs/superpowers/meta-review-protocol.md 头部；盲测材料=#106 r1 原文〔git 1ff91d2d〕/#103 活跃文本/外部锚定 prereg/#119 T2）： - T1 面（三臂一致＋亲验证实）：src/shenbi/pipeline/review_checklist.py:362（仅 import 常量 TRANSITION_CAP_PER_1000）＋:388-391（自算 ceil(CAP×max(wc,1)/1000)、计数 ≥ 语义）vs src/shenbi/gates/g4/chapter_drafting.py:1000-1001（密度 _density > CAP FAIL）——「门 FAIL 章必不漏过评审」不变式依赖两套独立维护的谓词（密度 > vs 计数 ≥）与两次独立取的 wc 输入；全仓 grep 无 first_failing/门↔评审对齐性质测试。#119 残余清单已登记「谓词多源三处不同轴」，本件是其根因修复。 - T2 面（DS 算术＋GLM 复算吻合＋三臂一致）：docs/research/2026-11-15-quality-external-anchor-prereg.md:8「32 条已评分行」vs 更好 0／相当 73／更差 19＝92 次锚点比较（分母口径未写）；判据表四档在 n=12 下非划分——Fisher-z 半宽 1.96/√9≈0.653：CI 下限>0 需 ρ̂>0.575、>0.2 需 ρ̂≈0.695，故「0.3≤ρ<0.5 只作 rank」档 CI 必跨 0（与撤回档重叠、优先级未声明）、0.575≤ρ̂<0.695 三档皆不命中（无判定）、「可作读者代理」档实际门槛 ρ̂≈0.70；另：作者评人以 1/3 权重进面板均值与 ICC(2,k)（构念污染，且低 ICC 可被同一文档的设计选择机械触发→错误作废）；随机序阅读剥夺叙事语境（代入感/继续读意愿构念系统性衰减，未入威胁声明）；bootstrap 仅重抽章（评人测量误差当零、未按 2/5/5 分层）。人工面板未运行（r2 执行包就绪、$0 API、随用户组织）——修复窗口=跑前。 - T3 面（四臂/三臂一致）：docs/superpowers/specs/2026-11-15-spec103-highlight-distill.md:34（第四源「本窗口共振分 top 章的段落优先进候选」）——①median+5 在实测密集带 ~78-86（sd≈2.4-3.5）上阈值≈+1.5σ 悬于上界，每 12 章窗期望 0-1 章达标且无零候选告警（风格同质化后恒选零=恰在最需要时失明）；②章级分→段级范文＝层级错位（生态谬误）；③入池无资格集（修订中／审计未过／结构门 FAIL 章可入池）；④「读者信号」命名与启用未以 #115 外部锚定结论为门控（该研究自带 ρ<0.3 撤定位条款，#103 对其结论零依赖零回滚）。#103 现状 Design r1 未执行——修订在执行前落地即根因修复，执行后则是返工。

    触及的不变量维度：情绪节奏、能力活性（弱关联——T3 修订 #103 的选章/注入面；T1 为门检单源纪律面、T2 为测量判据面，无叙事维度触面）

    r1.1 修订（2026-11-24 · 实现审计回写；动机锚点逐条复核全准）： - T1 增补两项（评测科学席实测，协调者重跑）：①缓存版本未随公式 bump——src/shenbi/pipeline/review_checklist.py:105（version: int = 2），#119 T2 改了预算公式却没动版本号，旧缓存清单会带着旧预算被复用。T1 改谓词时同步 bump，并补「公式变更必须 bump 版本」的断言测试；②整数边界差一——wc 为 1000 的整数倍时评审预算比门少报一个（wc=3000：评审首个 ERROR 计数 3、门首个 FAIL 计数 4）。属 §3 已登记的 floor+1 替代案范围，本件维持行为零变化，只在性质测试里把这个边界写成显式用例。 - T1 字数口径已核同源：门侧 word_count_md 与评审侧 word_count_md_text 是同一函数族（正文 CJK 计数）——动机里「两次独立取的 wc 输入」不构成缺口，T1 范围足够。 - T3 修订清单补一行：#103:25（confidence=high 合取项自带第三个 ρ<0.3 回退条件）——本件全文未提 confidence。T3 改写 #103 时须一并处置这一行，与「启用前置挂钩 prereg r3 档位」对齐，避免两处 ρ<0.3 条款措辞不一。 - T3 承接 #115 T4 第二条：#115 原要改写 #103 的「anchors 第四源以 T3 结果为门」——该条由本件 T3 的「改名判官偏好源（shadow）＋启用前置挂钩 prereg r3 档位＋ρ<0.3 撤回条款」承接，#115 r2 已标注不再单独施工。 - 顺序：T2（面板跑前窗口）时间敏感——本件在 INDEX 提到第 2 位，紧随 #121。

    0. 根因

    三个工件都定型于 v8.1 测量语义 lens 之前（PR #383，2026-11-22），且各自缺一道当时不存在的机制：T1——「单源」义务在 #119 T2 被执行为常量级，谓词与输入不在义务面（v8.1 L1「单源须覆盖谓词与输入」正是补此）；T2——预注册判据表未经「分支互斥穷尽＋给定 n 每档可达」检查（v8.1 L4）；T3——选章/入池/门控设计未经活性/闭环/层级检查（v8.1 L1/L2/L3）。本件＝lens 的首批消费与清偿：把盲测实证缺陷修在各自不可逆动作之前（T2 面板跑前、T3 spec 执行前、T1 行为面扩散前）。

    1. 任务分解

    T1 · 谓词级单源＋门↔评审对齐性质测试

    • gates/g4/chapter_drafting.py 导出纯函数 transition_first_fail_count(wc: int) -> int（含 max(wc,1) 护栏与现行 ceil 口径——行为零变化；floor+1 替代案见 §3）；review_checklist.py:388-391 改为消费该函数、删本地公式；门侧 _check 的 FAIL 判定与该函数共享同一谓词表达（密度换算计数或反之，以最小改动面为准，plan 期定形）。
    • 性质测试（纯新增）：对 wc ∈ 0..30000 扫描断言「评审 ERROR 首个失败计数 ≤ 门 FAIL 首个失败计数」（保守向不变式的机械表达）；CAP 变更经单源自动传导。
    • 判据：git grep -n "TRANSITION_CAP_PER_1000" src/ 仅命中 chapter_drafting 单源及其函数消费方（review_checklist 不再 import 常量自算式）；性质测试绿；既有 re-pin 测试零行为变化（至多改 import 面）；just check 全绿。

    T2 · prereg 判据表 r3 修复（跑前窗口）

    • docs/research/2026-11-15-quality-external-anchor-prereg.md 增 r3 修正节（评分仍未开始——与 r2 同一合法性前提：冻结前修正）：
    • 判据表重写为单调穷尽划分（声明 first-match 优先级）＋每档可达域算术附表（n=12 半宽 0.653 的直接推论；「代理」档如实标注最小可测 ρ̂≈0.70；0.5≤ρ̂<0.695 设「证据不足/维持 shadow」档）；方向性预注册（期望 ρ>0）保留；
    • 作者评人移出主分析（面板均值与 ICC）→ 敏感性分析单列；主面板＝未读过本书的读者；
    • 阅读顺序双臂：自然序主臂＋随机序敏感性臂（或统一前情摘要卡——r3 内二选一定死）；「语境错配」入威胁声明并把随机序 ρ 解读为下界；
    • bootstrap 改章×评人双层重抽，或如实标注章-only 窄 CI 局限（二选一定死）；
    • 「92 次锚点比较」口径标注（分母＝锚点判定数非行数；执行期以 #110 动机节原始口径核实）。
    • docs/superpowers/specs/2026-11-15-spec115-quality-measurement-endogeneity.md T3 段若引用判据表口径，同步一句「以 prereg r3 为准」指针。
    • 判据：机械划分检查——ρ̂∈{-1..1 步长 0.01}×CI 形态枚举验证每情形恰落一档（一次性脚本，不入 tests）；作者不在主分析路径；双臂/双层表述在案；纯 docs 改动，just check docs 面绿。

    T3 · #103 执行前补面（spec 修订 r2）

    • 2026-11-15-spec103-highlight-distill.md 修订（Status: 加 Revised 2026-11-22）：

    2. 验收

    1. T1-T3 判据全绿；
    2. T1 行为差分＝零（全量测试无口径变化；性质测试为纯新增面）；
    3. T2 修复在人工面板启动前落地——若用户已组织面板，T2 改道为「跑后敏感性分析补节」并回价值门重裁；
    4. T3 修订入账后 #103 方可被取队执行（INDEX 依赖标注）。

    3. 风险与备选

    • T1 floor+1 替代案：floor(CAP×wc/1000)+1 全区间（含整千）精确对齐、消灭一字翻转（6000/6001）——但改变 #119 已裁定的「整千严一词保守向」行为，本件不混入（登记后续候选；如做须独立差分＋真实章回放验收）；
    • T2 与预注册冻结的张力：r3 仍属「评分开始前」修正（与 r2 同前提），合法性成立；面板已启动则触发验收 3 改道；
    • T3 修订面膨胀：仅修盲测实证四缺陷＋门控，不顺手扩 scope（#103 其余面维持 r1 裁定）；
    • 执行顺序：T2（时间窗）→ T1（独立）→ T3；三 task 无相互依赖，单 PR 或分 PR 由 plan 期定。

    4. 立项预答（价值门 ④⑤ 前置）

    ④ 博弈路径清单（假设修法全部实施，根因能否复发）： - T1：第三处消费方再手写公式 → 性质测试只护已知两方——缓解：函数成为唯一公共 API＋grep 常量直接使用面（AST lint 候选登记 P2）；门侧语义被绕开函数直改 → 单源谓词表达消解该路径； - T2：判据表被事后改写以适配实跑结果 → 预注册冻结纪律（修正仅限评分前）＋r3 节显式日期戳； - T3：#103 执行期绕过资格集/门控 → 资格集进 G4 红测；shadow 消费面零路由（#106 shadow 先例）；「未触及」敷衍逐问回执 → v8.1 已定无逐问回执＝无效复核。

    ⑤ 候选机制清单（buy-before-build）： - T1：lint_threshold_reconciliation（CONSTELLATION 单带工具——#119 已证不覆盖此面，非替代）；gates/shared.py 既有 helper 位＝函数落点候选； - T2：无既有机制（研究文档本体修订）； - T3：#115 已含 holdout/外部锚定面——复用其结论作门控而非新建验证机制；告警先例＝resonance_window_starved WARN（#106）。

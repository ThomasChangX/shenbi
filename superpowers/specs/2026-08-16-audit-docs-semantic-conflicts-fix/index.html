    C24 · 文档语义矛盾批量修复（docs-semantic-conflicts）

    背景（根因 + 证据）

    根因：同一规则在 spec/SKILL 正文/配置文档多处写下互相矛盾的版本（阈值、词表、流程、统计口径、状态机分支），无对账人无对账工具——读者（含 LLM agent）拿到哪个版本全凭运气，且矛盾会被后续修改继续放大（phase4 软残条 F764"零散不一致"打包条置本簇）。

    证据分组（56 条）： - 阈值/数值口径矛盾：F707（代表：覆盖率阈值 78% vs 文档 ≥80% floor）、F848（ngram-methodology 示例 +15.9% 标注满足 ">0.20"；6 字窗口实为 4 个 5 字串）、F876（worldbuilding 声称 11 truth files 实列 12）、F850（MUTUAL_SECRET 三处枚举 4/4/3 态）、F919（目标字数 20 万 vs 10 万）、F903（自 #23 补登 2026-08-30：shenbi-foreshadowing-resolve SKILL.md 内 CP 阈值三处矛盾——:24 CP_THRESHOLDS {GREEN_MAX:50, RED_NOW:100, FORCE_NEXT_CHAPTER:200} vs :66"CP > 200 必须下章兑现" vs :85 示例 CP=80 判 RED 区（80:180"[RED区] 总 CP > 200"；同族含 #23 P2 清单 F1012-F1014 类 skill 内部阈值/词表矛盾） - 流程/状态机矛盾：F837（memory-distill DOT 的 L2/L4 分支标签在 ch36 同时为真——互斥分支图漏跑 L2）、F852（intent-management DOT 无条件 Update vs 正文"若有变化则更新"）、F855（length-normalizing DOT 扩写路径无 ≥3000 复核节点）、F829（DOT 省略正文强制步骤）、F841（4 个 group- 内嵌 Contract YAML 与 frontmatter 互换 + 陈旧行号）、F853（review-group-plan 引用错误技能名 shenbi-reader-pull）、F810/F813/F801（三个技能缺 anti-rationalization 表；F810 兼缺陷证据格式节与本 skill 无关 + relationship_map 命名漂移；F813 兼 escalation_check 命名与实际 helper 漂移）、F874（review-sensitivity 缺陷证据格式段引用残缺）、F847（4 个 review skill 空引用悬空）、F893（5 个现行技能缺 DOT，含 4 个主力审计 group-） - INDEX/spec 体系矛盾：F935（INDEX 排序违反自身声明：🟠 P1 #26 排在 ⚪ #16 与 🟡 #25 之后）、F936（编号交叉引用 #6 不可解析：5 处引用但归档无编号标记）、F937（#4 依赖字段引用不存在 §J，实为 §2.9）、F938（spec 间 P2 条目逐字重复：T12-03/04/05/06 在 #19+#22）、F939（#17 总纲统计不闭合且加总差 1）、F940（#16 M 批量计数 98 vs unique 127 + 节结构损坏）、F941（#25 双重登记 PR 归因冲突）、F942（#5 设计 spec v1 遗留计数与自身矛盾：T1-T11 vs T1-T16 等）、F943（§9 预写文件名死链）、F944（T14 依据把活跃 #3 误标 archive）、F945（#3/INDEX "9 次实现"被纠正为"实现 16、接线 ~5"无勘误）、F946（#25 F1100 疑似误报——需勘误标注）、F949（truth-write-path R1 实证过期：ch55 现盘与描述不符）、F950（SDD prompt v6 "23 份全部产自同一轮"不实）、F913（goal-prompt 快照多处与现状矛盾）、F914（CHANGELOG "7-gate (G0-G7)" 自相矛盾）、F916（ADR-0009 shim 保留结论已失效） -     目标

    1. 簇内 56 条矛盾逐条裁决出唯一权威版本并同步所有出现处（不是简单删除其一，而是显式选定）
    2. 高复发面（阈值、计数、流程分支）结构性收口：文档只引用单源（C9 阈值表、C22 词表、C23 去数字化），不再自抄数值
    3. INDEX/spec 体系自洽：排序符合声明、编号可解析、跨 spec 重复与误报有勘误注

    任务分解

    T1 · 裁决规则先行

    1. 建立裁决次序表（写进本 spec 执行 plan）：代码/配置实值 > 最近设计决策（最新 spec/ADR）> 多数版本；每条裁决记录"保留版本 + 修改位置清单"
    2. 凡与 C9（阈值单源）/C22（词表）/C16（fixture 数据）重叠的条目，等对应 spec 定源后改引用，不在本 spec 内再造数值

    T2 · SKILL 正文矛盾修复（P2 主体）

    1. DOT↔正文不一致族（F829/F837/F841/F852/F855）：以 DOT 为权威流程（AGENTS.md：DOT 为权威过程定义）修正文，或修 DOT 漏分支——逐技能裁决
    2. 缺失件补齐（F801/F813/F893）：anti-rationalization 表 3 份补齐；5 个缺 DOT 技能补图（group-* 四件优先——主力审计技能）；F847/F874 证据格式空引用修复（指向四要素格式的正式定义处）
    3. 术语/命名统一（F810/F813/F851/F853/F885/F857/F850）：技能名、helper 名、字段枚举、评分刻度（统一 /100 与 AGENTS.md 0-100 口径）、中文术语
    4. 杂项（F788/F876/F883/F856/F819→C21/F1029）

    T3 · spec/INDEX 体系自洽

    1. INDEX 修复（F935/F936/F937/T1002）：排序按声明重排或改声明；#6 归档件补编号标记使 5 处引用可解析；§J→§2.9
    2. 跨 spec 重复/误报（F938/F941/F946/F949/F950/F945）：重复条目保留主登记、副本改指针；误报与过期实证加勘误注（不删原文，保留审计痕迹）
    3. 计数/统计闭合（F939/F940/F942/F943/F944/F913/F914/F916/F1156）：总纲统计重算；M 批量计数以 unique 计数订正；v1 遗留计数加"历史版本，以 v3 为准"注；ADR-0009 补失效注；F1156 的 12 skill 队列登记进 INDEX 待办或显式 void

    T4 · 配置注释与批量 M

    1. F1024（mypy 3.12→3.11 对齐支持底线）、T1307/F1025/F1028/F1157/T1505/F764 顺带清理

    验收标准（真实数据可复验）

    1. 抽样复验 10 条（F707/F837/F876/F885/F935/F936/F938/F948/F949/F1024）：每条在同一时点全仓只剩一个版本（git grep 对照裁决记录）；阈值类显示的是 C9 单源表的引用而非独立数值
    2. INDEX 机械自洽：排序符合优先级声明（脚本或人工过一遍）；#6 引用可解析（grep -rn "#6" docs/superpowers/specs/ | wc -l 各命中处可达编号标记）
    3. 5 个缺 DOT 技能（F893 清单）全部有 DOT 流程图（grep -l "flowchart\|graph TD\|graph LR" <skill>/SKILL.md 命中）

    5. just check 全绿；C23 的 doc-links 检查对本 spec 改动文件 0 断链

    风险与回滚

    • 风险：语义裁决可能改行为预期（如 DOT 补分支改变技能执行流）——纯文档矛盾先修；涉及行为语义的（F837/F852）与 C20 契约对账联动，分批出
    • 风险：56 条面广、人工量大——按 T2/T3/T4 分三个 PR，每 PR 附裁决表；M 级允许批量 codemod
    • 风险：勘误注（F946/F949/F950 类）可能与"归档不可变"惯例冲突——归档件勘误以 INDEX 侧登记替代原文改动（本 spec 执行时二选一落定）
    • 回滚：全部文档改动，零代码；分批可逆
